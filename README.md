# GEOSCAN — планирование и распределение беспилотных авиационных работ

Сервис принимает описание задания — область съёмки, тип съёмки, флот БВС,
площадки взлёта, запретные зоны, границы воздушного пространства, ветер — и
рассчитывает индивидуальные полётные задания для группы разнотипных
беспилотников, выгружая их в KML и GeoJSON.

Оптимизация ведётся по двум критериям сразу: минимум времени выполнения работ
(makespan) и минимум суммарного налёта. Переключение между ними — параметр α.

> **Состояние: каркас (эпик E0).** Конвейер собран и проходит целиком на всех
> тестовых сценариях, но стадии съёмки, покрытия, полёта, транзита и валидации
> работают на заглушках. Заглушки объявляют себя в каждом плане — в поле
> `stub_stages` и в предупреждениях. Подробно и честно — в
> [`docs/current_state.md`](docs/current_state.md).

## Запуск

### Всё сразу, на чистой машине

```bash
docker compose up
```

Интерфейс — <http://localhost:5173>, API и его документация —
<http://localhost:8000/docs>. Тестовые сценарии подгружаются автоматически:
чтобы увидеть результат, рисовать полигон не нужно.

### Только ядро, без веба

Ядро — самостоятельный Python-пакет без веб-зависимостей. Оно считает и
выгружает планы, даже если каталоги `api/` и `web/` удалить целиком.

```bash
pip install -e ".[dev]"
python -m core.cli scenarios/simple.json -o out/mission.geojson
```

Прогон на всех тестовых сценариях сразу, с выгрузкой KML и GeoJSON на каждый:

```bash
python -m core.cli --batch scenarios/ -o out/
```

Реестр физических допущений — то, из чего вырастает раздел «известные
ограничения»:

```bash
python -m core.cli assumptions --team-only
```

Промежуточные стадии конвейера одним файлом (для отладки и инспектора стадий):

```bash
python -m core.cli scenarios/nasty.json -o out/ --dump-stages out/
```

### Тесты и линтер

```bash
pytest
ruff check core api tests
ruff format core api tests
```

### Типы для фронтенда

Типы TypeScript порождаются из контракта и руками не пишутся. После **любой**
правки `core/schemas.py`:

```bash
python -m core.cli export-schema -o web/src/types/schema.json
cd web && npm run gen:types
```

## Как это устроено

Конвейер чистых стадий: каждая принимает типизированный вход, возвращает
типизированный выход и знает о соседях только через типы из `core/schemas.py`.

```
Scenario ──▶ SurveyPlan ──▶ CoverageSet ──▶ Allocation ──▶ Mission ──▶ Files
            (параметры     (галсы,         (вылеты по     (план +      (KML,
             съёмки)        обрезанные      бортам)        warnings)    GeoJSON)
                            по маске)
```

```
web/    React + TypeScript + Vite + Leaflet   ──REST + поллинг──▶  api/
api/    FastAPI, тонкий слой                  ──импорт─────────▶   core/
core/   чистый Python, ноль веб-зависимостей, собственный CLI
```

`core` не импортирует ничего из `api` и `web` — ни для чего, включая типы.
Это страховка: если веб-слой отстанет, демонстрировать всё равно есть что.

| Каталог | Что внутри |
|---|---|
| `core/schemas.py` | Общий контракт: `Scenario`, `Vehicle`, `Strip`, `Leg`, `Sortie`, `Mission` |
| `core/assumptions.py` | Все физические константы и допущения, каждое с источником |
| `core/geo/` | Проекции, рабочая маска области |
| `core/survey/` | Сенсорная модель: GSD, высота, шаг галсов, совместимость нагрузок |
| `core/coverage/` | Галсы, направление, обрезка по маске |
| `core/flight/` | Ветер, время и энергия по фазам полёта |
| `core/transit/` | Перелёты между галсами и до площадок |
| `core/allocate/` | Распределение по флоту, целевая функция, baseline |
| `core/validate/` | Проверка плана, список предупреждений |
| `core/export/` | KML и GeoJSON |
| `api/` | FastAPI: сценарии, фоновый расчёт, поллинг, отдача файлов |
| `web/` | Карта, запуск расчёта, метрики, предупреждения |
| `data/vehicles.yaml` | ТТХ БВС из официальных документов, с источником у каждого параметра |
| `scenarios/` | Тестовые сценарии: простой, средний и «злой» |

## Тестовые сценарии

| Сценарий | Что проверяет | Ожидаемый результат |
|---|---|---|
| `simple.json` | Сквозной путь целиком | План без ошибок, покрытие 13 из 13 галсов |
| `medium.json` | Невыпуклая область с отверстием, две запретные зоны, две площадки, отсев непригодного борта | План есть; Геоскан 201 исключён — у его RGB-камер в источнике нет размеров матрицы |
| `nasty.json` | Два отверстия, зона впритык к границе, обрезка воздушным пространством, ветер у предела | **Ошибки ожидаемы**: часть галсов не распределена, транзиты пересекают запретную зону (обход — E5) |

Прогонять нужно все три. Сценарий, который всегда зелёный, ничего не проверяет.

## Правила, которые нельзя нарушать

1. **Вся геометрия — в метрической проекции.** WGS84 живёт только на границах:
   вход сценария и выход экспорта. Ошибка от расчётов в градусах — тихая.
2. **`core` не знает про веб.** Ни одного импорта из `api`.
3. **`core/schemas.py` — общий контракт.** Правка ломает три потока работы
   сразу, поэтому только осознанно и с отметкой в `current_state.md`.
4. **Ветер — метеорологическая конвенция** (откуда дует). Перепутанный знак
   даёт зеркальный план, и это видно только на демонстрации.
5. **Физические константы — только в `core/assumptions.py`.** ТТХ БВС — только
   из `data/vehicles.yaml`, не выдумываются.
6. **Baseline никогда не удаляется** — это точка сравнения, которой измеряется
   эффективность оптимизатора.

## Лицензии и источники данных

Картографическая подложка — OpenStreetMap, лицензия ODbL, атрибуция
«© OpenStreetMap contributors» выводится на карте. Сервисы Google не
используются. Технические характеристики БВС взяты из официальных документов
производителя, лежащих в `docs/`; источник указан у каждого параметра в
`data/vehicles.yaml`.

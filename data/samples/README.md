# Образцы данных заказчика

**Получено:** 2026-09-24 вместе с запиской [`customer_note.docx`](customer_note.docx) («Описание файлов. К заданию на хакатон от ГК „Геоскан“»).

## 1. `survey_area_msk.kml` — область съёмки

| Показатель | Значение |
|---|---|
| Placemark / Polygon | 696 / 696 |
| Полигонов с отверстиями | 63 (178 колец `innerBoundaryIs`) |
| Суммарная площадь | **245,0 км²** (куски не перекрываются) |
| Габарит | 64,7 × 57,6 км |
| bbox WGS84 | 38,2970…39,3087 в.д., 54,7473…55,2655 с.ш. |
| Размер куска | медиана **5,4 га**, максимум 5 909,8 га, 83 куска нулевой площади |
| Высоты | нет, `altitudeMode = clampToGround` |
| Атрибуты | `<Schema id="500">` с полями `Description` (string) и `FID` (float); `FID` заполнен у 147 из 696 |

**Геометрия невалидна у 100 полигонов из 696** (4,8% площади): 45 — «Too few points in geometry component», 34 — «Ring Self-intersection», 17 — «Self-intersection».

Это прямо задевает инвариант «самопересечения отвергаются с указанием места» (заказчик, №9, №19): импортировать файл как есть — значит отвергнуть 100 кусков и не начать работу. Решение — [`docs/input_formats.md`](../../docs/input_formats.md) §2.3.

**Главное следствие для алгоритма:** это не «одно поле на 245 км²», а 696 разрозненных островков с медианой 5,4 га, разбросанных по прямоугольнику 65 × 58 км. Деление большой области сеткой (наша текущая заглушка E3) здесь бессмысленно: почти каждый кусок меньше одного вылета, и главные затраты — перелёты между кусками, а не покрытие куска галсами.

## 2. `zones_msk.kml` — зоны ограничений

| Показатель | Значение |
|---|---|
| Placemark | 341, геометрия `MultiGeometry → Polygon`, координаты 2D |
| bbox WGS84 | 22,15…49,17 в.д., 43,50…59,41 с.ш. — **вся европейская часть**, далеко за пределами области съёмки |
| Задевают bbox области съёмки | **6 зон**: 3 `врем_ограничение`, 2 `запретная_зона`, 1 `пост_ограничение` |
| Помечены поставщиком «Некорректная геометрия!» | 8 |
| Невалидных по shapely | 0 |

Атрибуты каждой зоны — `ExtendedData` с тремя `Data`: `Name`, `Altitudes`, `Type`; `<name>` дублирует `Name`, `<description>` дублирует `Altitudes`.

| `Type` | Зон |
|---|---|
| `врем_ограничение` | 137 |
| `запретная_зона` | 114 |
| `пост_ограничение` | 89 |
| `svo` | 1 |

`Altitudes` — **свободный текст**, а не число. Шаблоны по убыванию частоты:

| Шаблон | Зон |
|---|---|
| `От земли до N м (M фут) AMSL` | 169 |
| `От земли до FLN` | 38 |
| `От N м (M фут) AMSL до FLN` | 25 |
| `От земли до N м (M фут) AGL` | 20 |
| `От FLN до FLN` | 17 |
| `На всех высотах` | 3 |

К тексту высот бывает приписан абзац-исключение («Не распространяется на воздушные суда Министерства обороны…»), встречается префикс «Некорректная геометрия!» и опечатки распознавания: `фyт` с латинской `y`, «вьшолняюшие». Разбор должен это терпеть.

**Времени действия в файле нет вообще** — даже у 137 зон с типом `врем_ограничение`. Это и есть то, для чего заказчик просит предложить формат.

## 3. `obstacles_msk.kml` и `obstacles_primorye.kml` — высотные препятствия

Оба файла — плоские списки `Placemark` без папок, каждый с `<extrude>1</extrude>`: контур с высотой `Z` в координатах, выдавленный вверх. Высота `Z` одинакова у всех точек контура. Имя — `<name>UUWV100069 OTHER:COMMUNICATION_TOWER</name>`: идентификатор и тип.

| Показатель | `obstacles_msk` | `obstacles_primorye` |
|---|---|---|
| Placemark | 5 164 | 3 201 |
| Polygon / LineString | 5 044 / 120 | 3 145 / 56 |
| `altitudeMode` | `relativeToGround` 2 552, **`relativeToSeaFloor `** 2 612 | `absolute` 2 777, `relativeToGround` 424 |
| `Z`, м | 7,0…403,8, среднее 146,1 | 2,7…996,7, среднее 108,3 |
| Битых записей | 2 (`<coordinates>0.0, 0.0, 0.0</coordinates>`, без `<name>`) | 0 |

Самые частые типы: `OTHER:COMMUNICATION_TOWER`, `BUILDING`, `VEGETATION`, `OTHER:CHIMNEY`, `ANTENNA`, `OTHER:POWER_TRANSMISSION_PYLON`, `TREE`, `OTHER:LIGHT_SUPPORT_STRUCTURE`, `FENCE`, `NAVAID`, `SIGN`.

Две особенности, которые обязан знать импорт:

1. **`relativeToSeaFloor ` — с хвостовым пробелом и не из словаря KML.** По смыслу и по величинам `Z` это абсолютная отметка верхушки (AMSL), как `absolute` в файле по Приморью. Молча принимать нельзя — но и падать на этом нельзя: так выгружает сам заказчик.
2. **`Z` значит разное в зависимости от `altitudeMode`:** при `relativeToGround` это высота препятствия над землёй, при `absolute` / `relativeToSeaFloor ` — отметка верхушки над уровнем моря. Смешать их — значит получить в Приморье «мачту 997 м».

**Внутри bbox области съёмки** (`survey_area_msk.kml`) лежат **453 препятствия** из `obstacles_msk`. Считать их одной кучей нельзя — `Z` у них в разных датумах:

| Датум | Объектов | `Z` мин | медиана | макс | `Z` > 150 |
|---|---|---|---|---|---|
| `relativeToGround` — высота над землёй | 149 | 7,0 | 77,1 | **107,0** | 0 |
| `relativeToSeaFloor ` — отметка верхушки над уровнем моря | 304 | 135,1 | 167,1 | 345,3 | 252 |

Два следствия, и оба важные:

1. **Ни одно препятствие с честно записанной высотой над землёй не выше 107 м.** С нашим вертикальным запасом 50 м (`OBSTACLE_VERTICAL_CLEARANCE_M`) они перелетаются на 157 м — ниже любой высоты съёмки в нынешних сценариях. Такие препятствия опасны только при мелком GSD, когда высота съёмки сама опускается к сотне метров.
2. **304 объекта из 453 без рельефа выглядят вдвое выше, чем они есть:** 167 м «над уровнем моря» в районе с отметками 110–200 м — это мачта метров в тридцать. В таком виде они попадают и в высоты съёмки, и в эшелоны перелётов, и план обходит их зря. Это переводит ЦМР (E1, P1) из «приятно иметь» в то, что прямо определяет длину маршрутов на реальных данных.

Файл по Приморью с этой областью не пересекается — это второй регион, пригодный для отдельного сценария.

## Что из этого получается на импорте

С 2026-09-24 файлы читаются `core/geo/kml_import.py` (правила — [`docs/input_formats.md`](../../docs/input_formats.md)). Результат на этих образцах:

| Слой | Прочитано | Принято | Исправлено | Выброшено | Вне области |
|---|---|---|---|---|---|
| Область | 696 | **549** кусков, 245,0 км² | 5 | 135 | — |
| Зоны | 341 | **10** | 0 | 0 | 331 |
| Препятствия (МО) | 5 164 | **547** | 0 | 2 | 4 615 |

549 кусков вместо 561 уцелевшей записи — соседние куски с общей границей слиты в один: мультиполигон с частями, делящими ребро, некорректен по OGC. Отбор зон и препятствий — по описанному прямоугольнику области с запасом 5 км (`IMPORT_SELECT_MARGIN_M`), поэтому принятых препятствий больше, чем 453 «внутри голого bbox» из §3.

Готовый сценарий на этих файлах — [`scenarios/real/real_msk.json`](../../scenarios/real/real_msk.json), параметры задания к нему — [`scenarios/sources/real_msk/params.json`](../../scenarios/sources/real_msk/params.json). Связь сценария с этими файлами записана в [`scenarios/sources/manifest.json`](../../scenarios/sources/manifest.json); в вебе сценарий открыт для просмотра, файлы — в менеджере исходных данных.

## Как эти числа получены

Скриптами разбора на `shapely` + `pyproj` из окружения проекта; метрика — UTM по центру слоя. Скрипты одноразовые, в репозиторий не клались: числа выше проверяются тестами импорта (`tests/test_kml_import.py`), и расходиться они должны только осознанно.

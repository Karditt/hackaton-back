# Описание API

REST API — основной программный интерфейс сервиса: всё, что умеет веб, доступно
и отсюда. Интерактивный справочник со схемами каждого запроса и ответа —
**OpenAPI (Swagger)** по адресу <http://localhost:8000/docs> запущенного API
(`docker compose up` или `uvicorn api.main:app --port 8000`); машиночитаемая
схема — `/openapi.json`. Этот документ — то же самое для чтения без запуска:
модель работы, маршруты, пример сквозного сценария и ошибки.

Контракт данных (сценарий, план, отчёт импорта) — pydantic-модели
[`core/schemas.py`](../core/schemas.py); формат файлов выгрузки —
[`export_format.md`](export_format.md); формат входных слоёв KML —
[`input_formats.md`](input_formats.md).

## 1. Модель работы

- **Сценарий** — задание на планирование: область, зоны, препятствия, площадки,
  пул техники, параметры съёмки, сроки (`Scenario`). Приходит JSON целиком или
  собирается ядром из слоёв KML и параметров. Проверяется на приёме:
  самопересечение области — с местом, недопустимое значение — с полем.
- **Расчёт — фоновая задача.** `POST …/plan` сразу возвращает задачу (202),
  состояние опрашивается поллингом `GET /jobs/{id}`: `pending` → `running` →
  `done` или `failed`. Небольшие сценарии считаются секунды, 245 км² — около
  5 минут. Очереди сообщений нет — задача живёт внутри процесса API.
- **Итог расчёта** — `mission_status`: `feasible` (полный план, прошёл
  краш-тест) или `infeasible` (отчёт: причины и проверенные советы). Частичных
  планов нет.
- **Готовые планы сохраняются** (`storage/jobs/`, последние 30) и после
  перезапуска доступны в `GET /jobs` со всеми выгрузками.
- **Подсказки, фронт «срок — ресурс», подбор площадки** — тоже фоновые задачи со
  своей точкой поллинга; каждый их план — обычная задача расчёта
  (`plan_job_id`) со всеми выгрузками.

Авторизации нет — сервис однопользовательский, работает локально.

## 2. Пример: от файлов до полётных заданий

```bash
API=http://localhost:8000

# 1. Сценарий из слоёв KML и параметров (площадки — точками KML; без них места подберёт сервис)
curl -s -X POST $API/scenarios/import \
  -F area=@area.kml -F zones=@zones.kml -F obstacles=@obstacles.kml -F sites=@sites.kml \
  -F params="$(cat params.json)"
# → 201 {"id": "my-area", "name": "…", "report": {"area": {"read": 696, "kept": 549, …}, …}}

# 2. Расчёт
curl -s -X POST "$API/scenarios/my-area/plan?mode=min_makespan"
# → 202 {"id": "3f2c…", "state": "pending", …}

# 3. Поллинг, пока state не станет done или failed
curl -s $API/jobs/3f2c…
# → {"state": "done", "mission_status": "feasible", "algorithm": "local_search", …}

# 4. Итог: метрики, вылеты, расписание, причины и советы — все стадии конвейера
curl -s $API/jobs/3f2c…/result

# 5. Файлы: весь план, задание одного борта, всё архивом
curl -OJ "$API/jobs/3f2c…/export?format=kml"
curl -OJ "$API/jobs/3f2c…/export?format=kml&board=geoscan-gemini_1"
curl -OJ "$API/jobs/3f2c…/export?format=schedule"
curl -OJ $API/jobs/3f2c…/package
```

Список бортов плана (для `board`) — свойство `boards` выгрузки GeoJSON.

## 3. Маршруты

### Сценарии

| Маршрут | Что делает | Ответ |
|---|---|---|
| `GET /scenarios` | Список сценариев; `rejected` — файлы хранилища, не прочитанные по контракту, с причиной | 200 |
| `GET /scenarios/{id}` | Сценарий целиком | 200 / 404 |
| `POST /scenarios` | Сохранить сценарий JSON (тело — `Scenario`). Одноимённый перезаписывается | 201 `{id, name}` / 422 |
| `POST /scenarios/import` | Собрать сценарий из файлов (multipart): `area` (KML, обязательно), `zones`, `obstacles`, `sites` (KML), `params` (JSON-текст — сценарий без слоёв). Площадки: слой `sites` → площадки в `params` → подбор сервисом | 201 `{id, name, report}` / 422 |
| `GET /scenarios/{id}/layers` | Слои сценария в GeoJSON — для карты до расчёта; в свойствах — число объектов по видам и площадь | 200 |
| `GET /scenarios/{id}/files` | Исходные файлы сценария по видам (`area`, `zones`, `obstacles`, `sites`, `params`, `scenario`) со счётчиками импорта | 200 |
| `GET /scenarios/{id}/files/{kind}` | Скачать исходный файл | 200 / 404 |

`report` — отчёт импорта (`ImportReport`): по каждому слою «прочитано, принято,
исправлено, выброшено, вне области», площадь и замечания с кодами `import.*`
(например, `import.sites_auto` — площадки подобраны сервисом). Идентификатор
сценария — имя файла хранилища: буквы, цифры, `_`, `-`, `.`, до 100 знаков.

### Расчёт

| Маршрут | Параметры | Что делает |
|---|---|---|
| `POST /scenarios/{id}/plan` | `mode` = `min_makespan` \| `min_resource`; `allocator` = `local_search` (по умолчанию) \| `constructive` \| `baseline`; `alpha`, `seed` | Поставить расчёт; 202 — задача |
| `GET /jobs` | — | Все задачи, новые первыми, включая сохранённые до перезапуска |
| `GET /jobs/{id}` | — | Состояние задачи — точка поллинга |
| `GET /jobs/{id}/result` | — | `PipelineResult`: все стадии — параметры съёмки, подобласти, распределение, покрытие, план (`mission`) с метриками, вылетами, расписанием, причинами и советами |
| `GET /jobs/{id}/schedule` | — | Расписание вылетов; у невыполнимого — пусто |
| `GET /jobs/{id}/export` | `format` = `geojson` \| `kml` \| `schedule`; `board` — задание одного борта | Файл-вложение; невыполнимый план — отчёт |
| `GET /jobs/{id}/package` | — | Весь комплект ZIP: обзор GeoJSON и KML, расписание CSV, KML каждого борта |

`allocator=baseline` — равное деление площади между бортами, точка сравнения
для оптимизатора.

### Вопросы о плане

| Маршрут | Параметры | Что делает |
|---|---|---|
| `POST /scenarios/{id}/hints` | `boards=N` — срок при N бортах; `deadline_s` — сколько бортов к сроку; `sweep=true` — срок при каждом N | Подсказка по пулу техники; 202 |
| `GET /hints/{id}` | — | Состояние, `runs_done`, отчёт: прогоны по N, ответ фразой, `plan_job_id` плана ответа |
| `POST /scenarios/{id}/pareto` | `steps` — число промежуточных сроков (1–8) | Фронт «срок — ресурс»; 202 |
| `GET /pareto/{id}` | — | Точки по мере расчёта: срок, ресурс, доминируется ли, `plan_job_id` |
| `POST /scenarios/{id}/sites` | — | Подбор места ещё одной площадки; 202 |
| `GET /sites/{id}` | — | Пробы: «как есть» и кандидаты — место, срок, ресурс, `plan_job_id` |

Каждый ответ этих маршрутов подтверждён полным планом с краш-тестом.

### Справочники

| Маршрут | Что делает |
|---|---|
| `GET /health` | Живость сервиса и каталога техники |
| `GET /vehicles` | Каталог моделей БВС с ТТХ, источниками и пробелами |
| `GET /assumptions` | Реестр допущений: значение, единицы, источник, вид (`?team_only=true` — только допущения команды) |
| `GET /park`, `PUT /park` | Парк техники вкладки «Техника» |

## 4. Ошибки

| Код | Когда | Тело |
|---|---|---|
| 404 | Нет сценария, задачи, борта в плане, исходного файла | `{"detail": "…"}` |
| 409 | Результат запрошен, пока расчёт идёт | `{"detail": "Расчёт ещё идёт: running"}` |
| 410 | Сохранённый план прошлого запуска больше не читается | `{"detail": "…"}` |
| 422 | Вход не принят: ошибка контракта — список полей с местом; ошибка содержания (самопересечение с координатами, область больше допустимой, неизвестный борт, перекрытие ниже минимума) — строка | `{"detail": [...]}` или `{"detail": "…"}` |

Невыполнимое задание — **не ошибка**: задача завершается `done` с
`mission_status: "infeasible"`, причины и советы — в `/result`, отчёт — в
`/export`.

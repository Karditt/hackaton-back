**Статус документа:** первоисточник требований наравне с ТЗ [`TZ_Geoscan.pdf`](TZ_Geoscan.pdf). Где ответ заказчика расходится с ТЗ или с нашими прежними допущениями, **действует ответ заказчика**.

## 1. Главное: что изменилось

### 1.1 Где мы копали не туда

| Прежнее направление | Что сказал заказчик | Что делаем теперь |
|---|---|---|
| Редактор сценария: рисование области, зон и площадок мышью (E10, P0) | Система **не должна** поддерживать ввод и редактирование объектов на карте: для этого есть ГИС-программы (№8, №12) | Геометрия приходит **файлами** (GeoJSON/KML) через API и загрузку в вебе. Рисование исключено из объёма |
| Офлайн-режим: тайлы кешируются, внешние API в рантайме запрещены | Требования на офлайн нет, интернет считать доступным (№16). Ограничений на внешние данные и облачные API нет (№18) | Запрет снят. Онлайн-источники (подложка, ЦМР) допустимы при условии кеша и понятной ошибки при недоступности |
| Ветер в модели времени и энергии: треугольник скоростей меняет путевую скорость и расход | На галсе автопилот держит **постоянную путевую скорость**, поэтому на время ветер почти не влияет. Для расхода заряда ветер не учитывать (№36, №45) | Ветер определяет **выполнимость** (удержит ли автопилот путевую скорость) и **направление галсов** и заход на галс. Из времени и энергии убирается |
| Пофазная модель энергии с множителями мощности | Линейной модели достаточно, лучше заложить запас (№35) | Расход линеен по полётному времени, отсечка 20% (№34) |
| Частичный план: нераспределённые галсы + предупреждения уровня ОШИБКА (`nasty.json`) | Задание **либо выполнено полностью, либо невыполнимо**. Частичный план избыточен (№33, №42) | Выход — полный план или отчёт о невыполнимости: причина и что добавить (площадку, борт, другую модель, подождать окончания временного запрета) |
| Своя физика сенсора на каждый тип съёмки (LiDAR, геофизика) | Качество — это GSD. По GSD, углу поля зрения и разрешению матрицы считается высота. Этого достаточно (№26) | Одна модель «GSD → высота» для всех типов + конфиг перекрытий по типам съёмки (№25) |
| Точная геометрия петель разворота самолёта | Максимально упростить: защитные зоны, в которых самолёт маневрирует как сам считает нужным (№38) | Петля не строится. Строится **зона манёвра** на концах галсов, она проверяется на конфликты |
| Масштабируемость по времени расчёта как ключевой аргумент (E12) | Жёсткого лимита нет, ориентир — 30 минут, качество важнее скорости, это не определяющий критерий (№3) | Бенчмарк времени расчёта понижен до P2. Время позволяет вести оптимизацию тщательнее и держать одну полную модель полёта |

### 1.2 Что недооценили — становится обязательным

| Требование | Откуда | Было |
|---|---|---|
| **Безопасность плана — главный способ проверки** («краш-тест»): нет столкновений и опасных сближений, нет залёта в запретные зоны, нет опасных пролётов у высотных препятствий | №4 | Обход зон (E5) и проверки (E7) — P1, разведение бортов — «режется третьим» |
| **Слой высотных препятствий** — отдельный входной слой | №2, №44 | Отсутствовал |
| **Масштаб:** область ~100 км², до 10 бортов (типично 10–15) | №2, №43 | Тестовые сценарии ~5 км² — в 20 раз меньше |
| **Коридор высот:** съёмка на одной высоте, высота меняется только на перелётах в пределах коридора (пример: съёмка 150 м, коридор до 700 м — чтобы развести борта) | №10 | Отсутствовал |
| **Запретные зоны — пространственно-временные:** горизонталь, высоты и окна времени; постоянные (аэродром) и временные (ОРВД) | №40 | Высоты зоны игнорировались, времени не было |
| **Минимумы разделения:** к «зависшему» самолёту (круг ожидания) не ближе ~300 м, к зависшему коптеру — 50 м | №37 | Отсутствовали |
| **Расписание** — обязательный выход | №31 | Было время старта вылета, но не как самостоятельный результат |
| **Описание формата выгрузки** — обязательно («задокументируйте, как всё будет храниться») | №21 | Не планировалось |
| **Мультиполигон** с отверстиями, без самопересечений; самопересечения — ошибка валидации | №9, №19 | Одиночный полигон; самопересечения молча чинятся `buffer(0)` |
| **Разные площадки взлёта и посадки** в одном вылете | №29 | Один `site_id` на вылет |
| **Ресурс борта** = налёт + циклы взлёт-посадка; режим «минимум ресурса при ограничении по сроку» | №23 | Суммарный налёт без циклов, ограничения по сроку нет |
| **Высота — над поверхностью (AGL)**, её держит автопилот; рельеф «считайте, что есть» | №10 | Высота над точкой старта, ЦМР вне объёма |
| **Ядро задачи — разделение работ между бортами** | №46, №27 | Совпадает, но покрытие строилось общей сеткой галсов на весь флот |

### 1.3 Что подтвердилось

- Резерв заряда 20% — теперь **значение заказчика**, а не допущение команды (№34).
- Шаг галсов считается из целевого поперечного перекрытия (№24); минимум для аэрофотосъёмки — 50% (№25). Наше значение по умолчанию 60% допустимо.
- Несколько вылетов одного борта — да (№32).
- Одну область можно делить между бортами, в том числе с разными моделями камер одного типа (№27).
- WGS84 на входе и выходе (№10, №21). Внутренняя метрическая проекция — наша деталь реализации, инвариант 1 остаётся.
- Запуск — `docker compose` (№17). Описание API — OpenAPI (№20), FastAPI отдаёт его сам.
- Авторизация, роли, восстановление после сбоя — не нужны (№15).
- Направление ветра нужно (№45) — метеорологическая конвенция (инвариант 4) остаётся.
- Взлёт с катапульты и парашютную посадку можно не моделировать (№39).

### 1.4 Бонусы — оценят, но не обязательно

- Подбор мест площадок взлёта сервисом — «будет вообще шикарно» (№28).
- Маршрут захода на посадку для самолётного типа (№30).
- История расчётов, версии маршрутов, сравнение вариантов плана (№14).
- Удобный веб-интерфейс сверх визуализации маршрутов (№11).
- Учёт времени суток с учётом сезона и нижней границы облачности (№22).

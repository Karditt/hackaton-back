# Формат выгрузки

Требование заказчика (№21): «Структуру KML вы определяете самостоятельно… Задокументируйте, как всё будет храниться. Если вам покажется, что KML неудобен, вы можете предложить доп. файлы с обоснованием». Этот документ описывает все файлы, которые отдаёт сервис, так, чтобы их можно было прочитать без нашего кода.

Версия формата: **`geoscan-planner/3`** (свойство `format` коллекции GeoJSON и `ExtendedData` документа KML).

**Что изменилось по сравнению с `/2`** (2026-09-19, долги №30–33): индивидуальное задание на каждый борт; ключевые точки; трек `gx:Track` для проигрывания полёта; расписание внутри KML; время — UTC до целой секунды с «Z» либо явно относительное; идентификатор борта `board_id`; ориентация колец полигонов по RFC 7946; цвета KML исправлены (были записаны не в том порядке байт).

## 1. Файлы

Комплект одного расчёта:

| Файл | Что внутри | Кому |
|---|---|---|
| `<сценарий>.geojson` | Весь план или отчёт о невыполнимости: маршруты, ключевые точки, подобласти, слои сценария, метрики, расписание | Программам: карта веба, интеграции |
| `<сценарий>.kml` | Весь план или отчёт — обзор: расписание, задания всех бортов, слои сценария | Людям и ГИС: Google Earth, QGIS |
| `<сценарий>.schedule.csv` | Расписание всех вылетов — таблица | Людям на площадке, таблицы |
| `<сценарий>.<board_id>.kml` | **Индивидуальное полётное задание одного борта** (ТЗ): его вылеты, ключевые точки, треки, его расписание и слои сценария | Экипажу борта, наземной станции |

У невыполнимого плана бортовых заданий нет — только три файла отчёта (частичных планов не бывает, инвариант 10).

Как получить:

| Что | CLI | API |
|---|---|---|
| Весь комплект | `python -m core.cli <сценарий>.json -o out/` — каталог | `GET /jobs/{id}/package` — архив ZIP с теми же файлами |
| Один файл на весь план | `-o out/plan.kml` — формат по расширению: `.geojson`/`.json`, `.kml`, `.csv` | `GET /jobs/{id}/export?format=geojson\|kml\|schedule` |
| Задание одного борта | `-o out/b.kml --board geoscan-gemini_1` | `GET /jobs/{id}/export?format=kml&board=geoscan-gemini_1` |

Параметр `board` работает со всеми тремя форматами: GeoJSON и CSV одного борта тоже можно получить. Неизвестный борт — ошибка со списком бортов плана (в API — 404). Список бортов — свойство `boards` коллекции GeoJSON (§4.1). Расписание также доступно JSON: `GET /jobs/{id}/schedule`. Полный результат со всеми стадиями конвейера — `GET /jobs/{id}/result` (схема — OpenAPI `/docs`).

**Почему ZIP, а не KMZ.** KMZ — это ZIP, внутри которого Google Earth открывает один `doc.kml`. Комплект содержит GeoJSON и CSV, а задания бортов нужны отдельными файлами, которые раздаются экипажам, — поэтому обычный архив. Записи архива датированы 1980-01-01: один расчёт даёт побитово один и тот же архив.

**Расписание в трёх местах, и зачем CSV.** Расписание лежит в KML (папка «Расписание», §5.3), в GeoJSON (свойство `schedule`) и в CSV. Строки одни и те же — они собираются в одном месте кода. CSV оставлен отдельным файлом (№21, «доп. файлы с обоснованием»): его без подготовки открывает любая таблица, а KML — нет. Убрать CSV можно без потерь.

### Борт

**Борт** — физический экземпляр модели из флота сценария. Его идентификатор `board_id` = `<модель>_<номер экземпляра с единицы>`, например `geoscan-gemini_3`: третий Gemini флота. Так же он подписан в интерфейсе (`geoscan-gemini #3`) и так же называется его файл задания.

**Вылет** — `sortie_id` = `<board_id>-t<номер вылета борта с единицы>`: `geoscan-gemini_3-t1` — первый вылет третьего Gemini, в KML — «Вылет 1» в папке «geoscan-gemini #3». Номера в `board_id` и `sortie_id` те же, что видит человек.

Рядом встречаются поля контракта `vehicle_id` (модель из каталога), `vehicle_instance` (номер экземпляра **с нуля**) и `trip_index` (номер вылета борта **с нуля**) — для программ. Людям — `board_id`, `sortie_id` и «вылет N».

## 2. Общие соглашения

| Что | Как |
|---|---|
| Система координат | WGS84, EPSG:4326 (заказчик, №10, №21). Порядок — долгота, широта |
| Высота | Метры **над поверхностью (AGL)**. Её держит автопилот (№10). В KML — `altitudeMode = relativeToGround` явно у каждой геометрии; слои на земле — `clampToGround` |
| Время | Секунды от начала работ (`start_s`, `end_s`, `time_s`) — всегда. Если в сценарии задано начало работ `start_time`, рядом — абсолютное время **UTC `YYYY-MM-DDThh:mm:ssZ`**, до целой секунды (тип `dateTime` XML Schema: его читают KML, ISO 8601 и таблицы) |
| Время без начала работ | Абсолютного времени нет, и оно **не придумывается** (подставить «сейчас» — значит получать разные файлы из одного сценария). Моменты подписаны `T+чч:мм:сс` от начала работ; в KML нет элементов времени и трека, и это написано в описании документа; в GeoJSON `time_reference = "relative"`. Все тестовые сценарии задают `start_time` |
| Подписи моментов | `06:12:30 UTC`; если момент не в день начала работ — с датой: `21.09 02:00:00 UTC` |
| Полигоны | Кольца замкнуты. Внешнее — против часовой стрелки, отверстия — по часовой: так требуют RFC 7946 (§3.1.6) и справочник KML (Google Earth заливает только лицевую сторону) |
| Расстояния, скорости | Метры, м/с |
| Внутренняя проекция | Расчёт идёт в UTM по центру области (`crs.epsg_working`); наружу — только WGS84 |

**Статус.** Выход всегда один из двух (инвариант 10):
- `feasible` — полный план: маршруты всех вылетов, ключевые точки, расписание, метрики;
- `infeasible` — отчёт: маршрутов нет, есть причины (с местами нарушений на карте) и рекомендации (с предлагаемыми местами площадок).

## 3. Ключевые точки

Ключевые точки — границы этапов полёта, которые назвал заказчик (№30: взлёт, перелёт, площадная съёмка, посадка). На каждый вылет:

| `keypoint` | Где | Высота | Когда |
|---|---|---|---|
| `takeoff` — «Взлёт» | Площадка взлёта | 0 | Начало фазы взлёта = `start_s` в расписании |
| `survey_start` — «Начало съёмки <подобласть>» | Первая точка первого галса подобласти | Высота съёмки | Момент прохождения |
| `survey_end` — «Конец съёмки <подобласть>» | Последняя точка последнего галса подобласти | Высота съёмки | Момент прохождения |
| `landing` — «Посадка» | Площадка посадки | 0 | Конец фазы посадки = `end_s` в расписании |

Пара «начало — конец съёмки» — на каждую подобласть вылета. Между ними и площадками — перелёты на эшелоне; набор высоты и снижение идут вертикально над площадкой и видны в треке и в KML-участках фаз `climb`, `descent`.

## 4. GeoJSON (RFC 7946)

`FeatureCollection`. Метаданные — в свойстве `properties` коллекции (RFC 7946 допускает сторонние члены).

### 4.1 Свойства коллекции

| Поле | Тип | Смысл |
|---|---|---|
| `format` | строка | `geoscan-planner/3` |
| `status` | `feasible` \| `infeasible` | Итог расчёта |
| `mission_id`, `scenario_id` | строка | Идентификаторы |
| `board_id` | строка \| null | Борт, если это задание одного борта; null — весь план |
| `mode` | `min_makespan` \| `min_resource` | Режим оптимизации (№23) |
| `algorithm` | строка | Например, `baseline:uniform_split` |
| `alpha`, `seed` | число | Вес свёртки для фронта Парето, зерно ГПСЧ |
| `altitude_mode`, `altitude_reference` | строка | `relativeToGround`, `AGL` |
| `time_reference` | `utc` \| `relative` | Есть ли абсолютное время (§2) |
| `start_time` | UTC \| null | Начало работ |
| `crs` | объект | `epsg_working`, `name` — внутренняя проекция, справочно |
| `metrics` | объект \| null | Метрики **всего плана**: срок, ресурс, налёт, циклы, число вылетов и бортов, покрытие, дедлайн. У невыполнимого — `null` |
| `boards` | массив | Борта файла: `board_id`, `label`, `vehicle_id`, `vehicle_instance`, `sortie_count`, `flight_time_s`, `first_takeoff_s`, `last_landing_s`. У невыполнимого — пусто |
| `schedule` | массив | Строки расписания — те же колонки, что в CSV (§6) |
| `reasons` | массив | Причины невыполнимости: `code`, `stage`, `message`, `context` |
| `recommendations` | массив | Что добавить: `kind` (`add_site`, `add_vehicle`, `add_batteries`, `other_model`, `wait`, `relax_requirement`), `message` |
| `stub_stages` | массив | Стадии конвейера, работавшие на заглушке |
| `warnings` | массив | Предупреждения, не ломающие план |

### 4.2 Признаки: поле `kind`

Порядок в файле: по бортам и вылетам — участки маршрута и ключевые точки; затем подобласти и зоны манёвра; места нарушений и предлагаемые площадки; слои сценария.

| `kind` | Геометрия | Когда есть | Свойства |
|---|---|---|---|
| `leg` | LineString с высотой третьей координатой | выполнимый план | `sortie_id`, `board_id`, `vehicle_id`, `vehicle_instance`, `trip_index`, `takeoff_site_id`, `landing_site_id`, `phase`, `cell_id`, `strip_id`, `length_m`, `duration_s`, `ground_speed_mps`, `altitude_m`, `start_s`, `end_s`, `start_time`, `end_time` |
| `keypoint` | Point с высотой третьей координатой | выполнимый план | `keypoint` (§3), `title`, `sortie_id`, `board_id`, `vehicle_id`, `vehicle_instance`, `trip_index`, `cell_id`, `site_id`, `altitude_m`, `time_s`, `time` |
| `survey_cell` | Polygon | выполнимый план | `cell_id`, `sortie_id`, `board_id`, `vehicle_id`, `area_m2` — подобласть, которую снимает вылет |
| `maneuver_zone` | Polygon | выполнимый план, самолётный тип | `cell_id`, `sortie_id`, `board_id`, `vehicle_id` — защитная зона на концах галсов (№38) |
| `violation` | LineString | невыполнимый план | `code`, `message` — где нарушено жёсткое правило |
| `recommended_site` | Point | невыполнимый план | `recommendation`, `message` — предлагаемое место площадки |
| `survey_area` | MultiPolygon | всегда | `name` |
| `no_fly_zone` | Polygon | всегда | `id`, `name`, `min_alt_m`, `max_alt_m`, `active_from`, `active_to` |
| `airspace_boundary` | Polygon | если задана | — |
| `obstacle` | Point или Polygon | всегда | `id`, `name`, `height_m` |
| `site` | Point | всегда | `site_id`, `name`, `site_kind` (`primary` \| `reserve`) |

Фазы участка (`phase`): `takeoff`, `climb`, `transit`, `strip` (галс — полезная работа), `turn`, `hold`, `descent`, `landing`. Наземные и вертикальные фазы в плане — одна точка и в GeoJSON участками не выводятся: большинство просмотрщиков рисует такую линию точкой нулевой длины. Их моменты — в ключевых точках, длительность — во времени соседних участков.

В задании одного борта (`board`) — только его участки, ключевые точки, подобласти и зоны манёвра; слои сценария — целиком.

**Слои сценария до расчёта** отдаёт `GET /scenarios/{id}/layers` (`core/export/geojson.py`, `scenario_to_geojson`): те же пять видов — `survey_area`, `no_fly_zone`, `airspace_boundary`, `obstacle`, `site` — с теми же свойствами. В свойствах коллекции — `format`, `scenario_id`, `name`, `altitude_reference`, `area_km2` (площадь области в метрической проекции; `null`, если геометрия некорректна) и `counts` — число объектов по видам. Это не файл выгрузки, а документ для показа исходных данных в интерфейсе.

**Если направление галсов борт определяет сам** (№21: «комбинация линий и полигонов»), достаточно признаков `survey_cell` вылета: это полигон, который надо снять, с высотой съёмки из `leg` фазы `strip` или из ключевой точки `survey_start`.

## 5. KML (OGC KML 2.2 + расширение Google `gx`)

### 5.1 Структура

```
Document                                  имя сценария; у задания — «<сценарий> — <борт>»
├─ description                            итог, как читать время и высоты, состав папок (HTML)
├─ Style, StyleMap …                      фазы, ключевые точки, трек, слои
├─ ExtendedData                           format, status, mission_id, scenario_id, board_id,
│                                         mode, algorithm, altitude_reference, time_reference, start_time
├─ Folder «Расписание»                    таблица в описании; строка на вылет (§5.3)
├─ Folder «Полётные задания»
│   └─ Folder «<борт>»                    geoscan-gemini #3; ExtendedData — сводка борта
│       └─ Folder «Вылет N · 06:00:00–06:44:10 UTC»   ExtendedData — строка расписания
│           ├─ Placemark «Взлёт · 06:00:00 UTC»          Point, TimeStamp
│           ├─ Placemark «Начало съёмки c-3 · …»        Point, TimeStamp
│           ├─ Placemark «Конец съёмки c-3 · …»         Point, TimeStamp
│           ├─ Placemark «Посадка · …»                  Point, TimeStamp
│           ├─ Placemark «Трек 4D»                       gx:Track
│           ├─ Folder «Маршрут по фазам»                 LineString на участок, TimeSpan
│           └─ Folder «Подобласти»                       Polygon подобластей и зон манёвра
├─ Folder «Причины невыполнимости»        только у невыполнимого
├─ Folder «Рекомендации»                  только у невыполнимого
└─ Folder «Сценарий»                      область, зоны, граница пространства, препятствия, площадки
```

В обзоре папки бортов свёрнуты, в задании борта — его папка раскрыта. `Snippet` документа пуст: иначе Google Earth показывал бы в списке начало длинного описания.

### 5.2 Объекты и атрибуты

Машиночитаемые атрибуты — в `ExtendedData` (`<Data name="…"><value>…</value></Data>`), поле `kind` называет объект так же, как в GeoJSON:

| Объект | `kind` | Атрибуты |
|---|---|---|
| Папка борта | `board` | как элемент `boards` в GeoJSON (§4.1) |
| Папка вылета | `sortie` | строка расписания (§6) и `survey_altitude_m`, `distance_m`, `energy_fraction_used`, `cell_ids` |
| Ключевая точка | `keypoint` | `keypoint`, `sortie_id`, `board_id`, `cell_id`, `site_id`, `altitude_agl_m`, `time_s`, `time_utc` |
| Трек | `track` | `sortie_id`, `board_id` |
| Участок маршрута | `leg` | `sortie_id`, `board_id`, `phase`, `cell_id`, `strip_id`, `length_m`, `duration_s`, `ground_speed_mps`, `altitude_agl_m`, `start_s`, `end_s` |
| Подобласть, зона манёвра | `survey_cell`, `maneuver_zone` | `cell_id`, `sortie_id`, `area_m2` |
| Строка расписания | `schedule_entry` | колонки CSV (§6) |
| Слои сценария | `survey_area`, `no_fly_zone`, `airspace_boundary`, `obstacle`, `site` | как в GeoJSON |
| Отчёт | `violation`, `recommended_site` | `code`, `stage` / `recommendation` |

Участки маршрута: имя «NN · фаза», у галса — с идентификатором галса. Набор высоты и снижение выводятся вертикальными линиями над площадкой: в 3D это настоящая линия. Наземные фазы (взлёт, посадка) — одна точка в один момент — участком не выводятся, их моменты — ключевые точки.

Препятствие поднято на свою высоту и вытянуто к земле (`extrude`): мачта в Google Earth — вертикальная линия, здание — объём. Запретная зона лежит на земле; её высоты и окно действия — в описании и `ExtendedData`, у временной зоны — `TimeSpan` окна.

### 5.3 Время и расписание

- **`TimeStamp`** — у ключевых точек: момент события.
- **`TimeSpan`** — у участков маршрута и строк расписания: от начала до конца.
- **`gx:Track`** — положение борта в каждый момент вылета: пары `when` (UTC) и `gx:coord` («долгота широта высота» через пробелы, высота AGL, `altitudeMode = relativeToGround`). Все `when` идут перед всеми `gx:coord`, число тех и других равно (схема `kml22gx.xsd`). Совпавшие после округления до секунды моменты схлопнуты в один. Google Earth по треку двигает метку борта на шкале времени; линия трека прозрачна, потому что маршрут уже нарисован участками по фазам. Трек — расширение Google: программы, которые его не знают, пропускают его, остальная выгрузка от него не зависит.
- **Папка «Расписание»** — вылеты по времени взлёта. В описании папки — HTML-таблица (Google Earth показывает её по щелчку на папке). Каждая строка — `Placemark` **без геометрии** (схема KML это допускает) с именем «06:00:00–06:44:10 UTC · geoscan-gemini_3 · вылет 1», `TimeSpan` и колонками расписания в `ExtendedData`: в Google Earth это пункт списка, в QGIS — запись таблицы атрибутов.

Без начала работ (§2) элементов времени и трека нет, моменты подписаны `T+чч:мм:сс`.

### 5.4 Стили

Цвет KML записывается как **`aabbggrr`** — альфа, синий, зелёный, красный, а не привычный `rrggbb`. Цвета фаз те же, что на карте веба: галс — красный `#dc2626` (в KML `f22626dc`), перелёт — серый, набор и снижение — голубые, разворот — оранжевый, посадка — синяя. В формате `/2` цвета фаз были записаны как `rrggbb`, и в Google Earth галсы выходили синими, а посадка — красной.

Ключевые точки — `StyleMap`: в обычном виде подпись на карте скрыта (иначе у площадки десятки наложенных подписей), при наведении — показывается. Цвет точки: взлёт — зелёный, начало съёмки — красный, конец съёмки — тёмно-красный, посадка — синяя. Внешних значков нет: файл не ходит в сеть.

### 5.5 Соответствие стандарту и чем проверено

- Порядок дочерних элементов — последовательности схемы OGC `ogckml22.xsd` и `kml22gx.xsd` (у Feature: `name`, `open`, `Snippet`, `description`, время, `styleUrl`, стили, `ExtendedData`, геометрия или вложенные Feature). Схема задаёт порядок, а не набор: нарушенный порядок строгие читатели отвергают, нестрогие молча теряют элементы. Тест `test_kml_follows_the_ogc_schema_order` проверяет это на обзоре, заданиях бортов и отчёте.
- Проверено двумя независимыми разборщиками KML в браузере — `@tmcw/togeojson` (Mapbox) и форматом KML OpenLayers (2026-09-19): все файлы разобраны без ошибок, число объектов совпадает, стили разрешаются в те же цвета, что в вебе, треки читаются со временем (togeojson — `coordTimes`, OpenLayers — линия XYZM).
- **Не проверено:** открытие в Google Earth Pro и QGIS — на машине разработки их нет.

**Как смотреть.** Google Earth Pro: «Файл → Открыть», шкала времени появляется сама; кнопка воспроизведения проигрывает полёт. QGIS: «Слой → Добавить слой → Векторный», каждая папка становится слоем; строки расписания — объекты без геометрии.

## 6. Расписание, CSV

UTF-8, разделитель — запятая, первая строка — заголовок. Строка на вылет, по времени взлёта. Те же строки — в KML (§5.3) и в свойстве `schedule` GeoJSON.

| Колонка | Единица | Смысл |
|---|---|---|
| `sortie_id` | — | Идентификатор вылета |
| `board_id` | — | Борт (§1) |
| `vehicle_id`, `vehicle_instance` | — | Модель борта и номер экземпляра (с нуля) |
| `trip_index` | — | Номер вылета этого борта (с нуля) |
| `takeoff_site_id`, `landing_site_id` | — | Площадки взлёта и посадки (могут различаться, №29) |
| `start_s`, `end_s` | с | Взлёт и посадка от начала работ, целые секунды |
| `duration_min` | мин | Полётное время |
| `start_time_utc`, `end_time_utc` | UTC | Если задано начало работ; иначе пусто |
| `delay_s` | с | На сколько старт сдвинут ради разведения бортов и окон временных зон |
| `transit_altitude_m` | м AGL | Эшелон перелёта борта |

У невыполнимого плана — только строка заголовка.

## 7. Что не выгружается

- Форматы наземных станций (`.plan` QGroundControl, `.waypoints` Mission Planner) — P2 (E8).
- Абсолютные высоты над уровнем моря — нет ЦМР (E1, P1); все высоты AGL.
- Траектория петли разворота самолёта — по решению заказчика (№38) вместо неё выгружается зона манёвра.
- Объём запретной зоны с нижней границей выше земли: KML не умеет «висящий» объём, зона лежит на земле, высоты — в атрибутах.

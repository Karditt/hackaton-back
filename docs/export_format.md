# Формат выгрузки

Требование заказчика (№21): «Структуру KML вы определяете самостоятельно… Задокументируйте, как всё будет храниться. Если вам покажется, что KML неудобен, вы можете предложить доп. файлы с обоснованием». Этот документ описывает все файлы, которые отдаёт сервис, так, чтобы их можно было прочитать без нашего кода.

Версия формата: **`geoscan-planner/2`** (свойство `format` коллекции GeoJSON).

---

## 1. Файлы

| Файл | Что внутри | CLI | API |
|---|---|---|---|
| `<сценарий>.geojson` | Полётное задание или отчёт о невыполнимости, со всеми слоями и метаданными | `python -m core.cli <сценарий>.json -o out/` | `GET /jobs/{id}/export?format=geojson` |
| `<сценарий>.kml` | То же для ГИС и Google Earth: маршруты по бортам и вылетам, метки времени | то же | `GET /jobs/{id}/export?format=kml` |
| `<сценарий>.schedule.csv` | Расписание вылетов — таблица | то же | `GET /jobs/{id}/export?format=schedule` |

Расписание также доступно JSON: `GET /jobs/{id}/schedule`. Полный результат со всеми стадиями конвейера — `GET /jobs/{id}/result` (схема — OpenAPI `/docs`).

**Какой формат выбирается в CLI.** Если `-o` указывает на каталог, пишутся все три файла. Если на файл — один, по расширению: `.geojson`/`.json` — GeoJSON, `.kml` — KML, `.csv` — расписание.

**Кто что читает.**

| Формат | Читатель | Зачем |
|---|---|---|
| GeoJSON | Программы: карта в нашем вебе (Leaflet понимает GeoJSON напрямую), внешние интеграции через API | Всё машиночитаемо: маршруты, подобласти, метрики, причины, рекомендации, расписание в свойствах коллекции |
| KML | Люди и ГИС: Google Earth, QGIS, наземная станция | Папки по бортам и вылетам, стили фаз, метки времени — полёт проигрывается на шкале времени |
| CSV | Люди на площадке, таблицы | Расписание одной таблицей. Дублирует данные GeoJSON — судьба файла не решена (§6) |

**Зачем отдельный CSV.** Расписание читают люди на площадках и загружают в таблицы. В GeoJSON и KML время есть, но разнесено по участкам маршрута. CSV открывается чем угодно и даёт одну строку на вылет.

## 2. Общие соглашения

| Что | Как |
|---|---|
| Система координат | WGS84, EPSG:4326 (заказчик, №10, №21). Порядок — долгота, широта |
| Высота | Метры **над поверхностью (AGL)**. Её держит автопилот (№10). В KML — `altitudeMode = relativeToGround` явно у каждой линии |
| Время | Секунды от начала работ (`start_s`, `end_s`). Если в сценарии задано `start_time`, рядом — абсолютное время UTC в ISO 8601 (`start_time`, `end_time`) |
| Расстояния | Метры; скорости — м/с |
| Внутренняя проекция | Расчёт идёт в UTM по центру области (`crs.epsg_working`); наружу — только WGS84 |

**Статус.** Выход всегда один из двух (инвариант 10):
- `feasible` — полный план: маршруты всех вылетов, расписание, метрики;
- `infeasible` — отчёт: маршрутов нет, есть причины (с местами нарушений на карте) и рекомендации (с предлагаемыми местами площадок). Частичных планов не бывает.

## 3. GeoJSON (RFC 7946)

`FeatureCollection`. Метаданные — в свойстве `properties` коллекции (RFC 7946 допускает сторонние члены).

### 3.1 Свойства коллекции

| Поле | Тип | Смысл |
|---|---|---|
| `format` | строка | `geoscan-planner/2` |
| `status` | `feasible` \| `infeasible` | Итог расчёта |
| `mission_id`, `scenario_id` | строка | Идентификаторы |
| `mode` | `min_makespan` \| `min_resource` | Режим оптимизации (№23) |
| `algorithm` | строка | Например, `baseline:uniform_split` |
| `alpha`, `seed` | число | Вес свёртки для фронта Парето, зерно ГПСЧ |
| `altitude_mode`, `altitude_reference` | строка | `relativeToGround`, `AGL` |
| `start_time` | ISO 8601 \| null | Начало работ |
| `crs` | объект | `epsg_working`, `name` — внутренняя проекция, справочно |
| `metrics` | объект \| null | Срок, ресурс, налёт, циклы, число вылетов и бортов, покрытие, дедлайн. У невыполнимого плана — `null` |
| `schedule` | массив | Строки расписания, как в CSV (§5). У невыполнимого — пусто |
| `reasons` | массив | Причины невыполнимости: `code`, `stage`, `message`, `context` |
| `recommendations` | массив | Что добавить: `kind` (`add_site`, `add_vehicle`, `add_batteries`, `other_model`, `wait`, `relax_requirement`), `message` |
| `stub_stages` | массив | Стадии конвейера, работавшие на заглушке |
| `warnings` | массив | Предупреждения, не ломающие план |

### 3.2 Признаки: поле `kind`

Порядок в файле: участки маршрута, подобласти и зоны манёвра, места нарушений и предлагаемые площадки, слои сценария.

| `kind` | Геометрия | Когда есть | Свойства |
|---|---|---|---|
| `leg` | LineString с высотой третьей координатой | выполнимый план | `sortie_id`, `vehicle_id`, `vehicle_instance`, `trip_index`, `takeoff_site_id`, `landing_site_id`, `phase`, `cell_id`, `strip_id`, `length_m`, `duration_s`, `ground_speed_mps`, `altitude_m`, `start_s`, `end_s`, `start_time`, `end_time` |
| `survey_cell` | Polygon | выполнимый план | `cell_id`, `sortie_id`, `vehicle_id`, `area_m2` — подобласть, которую снимает вылет |
| `maneuver_zone` | Polygon | выполнимый план, самолётный тип | `cell_id`, `vehicle_id` — защитная зона на концах галсов (№38) |
| `violation` | LineString | невыполнимый план | `code`, `message` — где нарушено жёсткое правило |
| `recommended_site` | Point | невыполнимый план | `recommendation`, `message` — предлагаемое место площадки |
| `survey_area` | MultiPolygon | всегда | `name` |
| `no_fly_zone` | Polygon | всегда | `id`, `name`, `min_alt_m`, `max_alt_m`, `active_from`, `active_to` |
| `airspace_boundary` | Polygon | если задана | — |
| `obstacle` | Point или Polygon | всегда | `id`, `name`, `height_m` |
| `site` | Point | всегда | `site_id`, `name`, `site_kind` (`primary` \| `reserve`) |

Фазы участка (`phase`): `takeoff`, `climb`, `transit`, `strip` (галс — полезная работа), `turn`, `hold`, `descent`, `landing`. Наземные и вертикальные фазы вырождаются в точку и в GeoJSON не выводятся: LineString из двух одинаковых точек невалиден по RFC 7946. Их длительность учтена во времени соседних участков.

**Если направление галсов борт определяет сам** (№21: «комбинация линий и полигонов»), достаточно признаков `survey_cell` вылета: это полигон, который надо снять, с высотой съёмки из `leg` фазы `strip`.

## 4. KML (OGC 2.2)

```
Document
├─ description        статус, режим, срок, налёт; у невыполнимого — причины
├─ Style …            стили фаз, подобластей, зон манёвра, зон, препятствий, нарушений
├─ Folder «Полётные задания»                      — только у выполнимого плана
│   └─ Folder «<борт> #<n>»
│       └─ Folder «Вылет <k> · <sortie_id>»      описание: площадки, старт, длительность, высоты
│           ├─ Placemark «NN · <фаза>»           LineString, altitudeMode = relativeToGround,
│           │                                     TimeSpan (если задано начало работ), ExtendedData
│           ├─ Placemark «Подобласть …»          Polygon, clampToGround
│           └─ Placemark «Зона манёвра …»        Polygon, clampToGround
├─ Folder «Причины невыполнимости»                — только у невыполнимого
├─ Folder «Рекомендации»                          — только у невыполнимого
└─ Folder «Сценарий»                              область, зоны (с TimeSpan у временных), препятствия, площадки
```

`ExtendedData` участка повторяет свойства `leg` из GeoJSON: `sortie_id`, `vehicle_id`, `phase`, `cell_id`, `strip_id`, `length_m`, `duration_s`, `ground_speed_mps`, `altitude_agl_m`, `start_s`, `end_s`. `TimeSpan` позволяет проиграть полёт на шкале времени Google Earth.

## 5. Расписание, CSV

UTF-8, разделитель — запятая, первая строка — заголовок. Строка на вылет, по времени взлёта.

| Колонка | Единица | Смысл |
|---|---|---|
| `sortie_id` | — | Идентификатор вылета |
| `vehicle_id`, `vehicle_instance` | — | Модель борта и номер экземпляра (с нуля) |
| `trip_index` | — | Номер вылета этого борта (с нуля) |
| `takeoff_site_id`, `landing_site_id` | — | Площадки взлёта и посадки (могут различаться, №29) |
| `start_s`, `end_s` | с | Взлёт и посадка от начала работ |
| `duration_min` | мин | Полётное время |
| `start_time_utc`, `end_time_utc` | ISO 8601 | Если задано начало работ; иначе пусто |
| `delay_s` | с | На сколько старт сдвинут ради разведения бортов и окон временных зон |
| `transit_altitude_m` | м AGL | Эшелон перелёта борта |

У невыполнимого плана — только строка заголовка.

## 6. Что не выгружается

- Форматы наземных станций (`.plan` QGroundControl, `.waypoints` Mission Planner) — P2 (E8).
- Абсолютные высоты над уровнем моря — нет ЦМР (E1, P1); все высоты AGL.
- Траектория петли разворота самолёта — по решению заказчика (№38) вместо неё выгружается зона манёвра.

### Открытые решения по формату

Разобраны 2026-09-18, изменения отложены. Подробности и варианты — [`current_state.md`](current_state.md) §5, долги №30–33.

| Пробел | Суть |
|---|---|
| Метки времени без даты начала | `TimeSpan` в KML есть только при заданном `start_time`; иначе время — секундами от начала в `ExtendedData` |
| Ключевые точки | Взлёт, начало и конец съёмки, посадка отдельными точками не выгружаются, хотя ТЗ требует «маршрут и ключевые точки» |
| Файл на каждый борт | ТЗ говорит о заданиях «для каждого БВС»; сейчас файл общий, борта — папками внутри |
| CSV | Дублирует расписание из GeoJSON; оставить необязательной копией или убрать, если расписание целиком переедет в KML |

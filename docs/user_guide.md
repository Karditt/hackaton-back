# Руководство пользователя

Сервис делит площадную аэрофотосъёмку между разнотипными беспилотниками:
по области съёмки, запретным зонам, препятствиям, площадкам и доступной
технике он рассчитывает полётное задание каждого борта и общее расписание — или
объясняет, почему задание невыполнимо и что добавить.

Руководство — для того, кто готовит задание и забирает результат. Как устроен
расчёт — [`architecture.md`](architecture.md), что решение упрощает —
[`known_limitations.md`](known_limitations.md), форматы файлов —
[`input_formats.md`](input_formats.md) и [`export_format.md`](export_format.md).

## 1. Запуск

**Всё сразу** (нужен Docker):

```bash
docker compose up
```

Интерфейс — <http://localhost:5173>, API с описанием OpenAPI —
<http://localhost:8000/docs>. Демонстрационные сценарии, в том числе два на
реальных данных Московской области (245 км², сотни зон и препятствий),
подгружаются сами.

**Без Docker** (Python 3.12 и Node.js 20+):

```bash
pip install -e ".[dev]"
uvicorn api.main:app --port 8000
cd web && npm install && npm run dev
```

**Только расчёт, без интерфейса** — командная строка ядра, §7.

## 2. Что нужно на вход

| Что | Откуда | Обязательно |
|---|---|---|
| Область съёмки | KML: полигоны, можно с отверстиями и сотнями островков | да |
| Зоны ограничений | KML: полигоны зон; высоты и окна действия — в описании зоны, формат — [`input_formats.md`](input_formats.md) §3.2 | нет |
| Высотные препятствия | KML: 3D-примитивы, линии, точки с высотой | нет |
| Параметры задания | JSON: тип съёмки и разрешение (GSD), пул техники, площадки взлёта-посадки, коридор высот, ветер, начало работ, срок, режим оптимизации | да |

Геометрию на карте не рисуют: её готовят в ГИС и загружают файлами. Параметры
задания правятся в интерфейсе (§3.2).

**Пул техники.** В параметрах перечисляются модели и сколько бортов каждой
доступно. Какие из них пойдут в работу, решает расчёт: борт, которому работы
не досталось, остаётся на земле, а в итоге указан состав плана. До 15 бортов в
пуле.

**Площадки.** Штатные — для работы; резервные — только для внештатной посадки и
ожидания. Борт можно приписать к площадке или оставить выбор расчёту.

**Режим оптимизации.**

- **Минимум срока** — работа заканчивается как можно раньше; в дело идёт столько
  техники, сколько помогает.
- **Минимум ресурса** — меньше всего налёта и циклов взлёт-посадка. Со сроком —
  минимум ресурса, но не позже срока.

Срок в обоих режимах — жёсткое ограничение: не укладываемся — задание
невыполнимо, и отчёт называет достижимый срок.

## 3. Работа в интерфейсе

### 3.1 Вкладки

- **«План и карта»** — выбор сценария, загрузка файлов, параметры задания,
  расчёт, подсказка по флоту, итог и карта.
- **«Расписание»** — диаграмма вылетов по бортам и таблицы во всю ширину.
- **«Техника»** — парк бортов, модели с характеристиками, полезная нагрузка.

Границу между панелью и картой можно перетаскивать.

### 3.2 Задание

1. **Сценарий** — выберите из списка; под списком — что в сценарии и сколько
   примерно идёт расчёт. Слои сценария сразу видны на карте:
   менеджер исходных данных на карте показывает область, зоны, препятствия,
   границу пространства, площадки — с числом объектов и площадью; показ каждого
   вида включается отдельно. У каждого вида — исходный файл со ссылкой на
   скачивание и итогом импорта.
2. **Свои файлы** — кнопка «Загрузить» у вида данных в менеджере. Можно
   загрузить слои KML и параметры, а можно сценарий целиком (JSON). «Собрать
   сценарий» отправляет файлы на сервер; вид, файла которого не загрузили,
   берётся у выбранного сценария — так заменяется, например, только слой
   препятствий. Итог импорта — сколько объектов прочитано, принято, исправлено,
   выброшено и отброшено как лежащие вне области — показывается под каждым видом:
   молча ничего не чинится и не выбрасывается. Новый сценарий получает пометку
   «(свои файлы)» и выбирается сразу.
3. **Параметры задания** — тип съёмки, GSD, пул техники (модель, число,
   нагрузка, площадка, комплекты АКБ), ветер, коридор высот, начало работ, срок,
   межвылетная подготовка, съёмка только при Солнце не ниже заданной высоты.
   Правка не трогает исходный файл: расчёт идёт по копии сценария с пометкой
   «(изменённые параметры)». Недопустимое значение сервис отвергает с названием
   поля и причиной.
4. **Критерий оптимальности** и **«Рассчитать»**. Небольшие сценарии считаются
   секунды, 245 км² — несколько минут; в шапке видно состояние расчёта.

### 3.3 Итог

**План выполним** — область покрыта целиком, проверка безопасности (краш-тест)
пройдена. В панели:

- **итог** — срок выполнения работ, ресурс техники (налёт плюс циклы
  взлёт-посадка), налёт, число вылетов и бортов, **состав плана** («3 × Геоскан
  201, 5 × Геоскан Gemini — 8 из 10 бортов пула») и кто остался на земле,
  протяжённость маршрутов, выполнение срока;
- **сравнение с равномерным делением** — тот же пул делит работу поровну по
  площади, как без оптимизатора; таблица «план / поровну / разница»;
- **замечания и справки** — что план не ломает, но стоит знать: общий эшелон у
  нескольких бортов, запас ветра у предела, недосягаемая запасная площадка,
  износ по нормативам ТО, какие способы распределения сравнивались; сначала
  замечания, потом справки;
- **выгрузка** — обзор плана в трёх форматах, архив всего комплекта и задание
  каждого борта (§5).

**Задание невыполнимо** — частичного плана нет. Панель называет причины
(например, «ни в один вылет не укладываются 3 подобласти», «работы занимают
7,20 ч при ограничении 6,00 ч») и что изменить: площадку — с местом на карте,
борт, комплекты АКБ, другую модель. Советы «площадка», «борт» и «комплекты АКБ»
проверены пересчётом задания — к совету дописан итог. Отчёт тоже выгружается.

**Карта.** Маршруты по фазам полёта, ключевые точки (взлёт, начало и конец
съёмки подобласти, посадка), подобласти, зоны манёвра самолётов, места
нарушений и предлагаемые площадки. Цвета фаз — в легенде панели «Данные и
слои»; щелчок по объекту показывает подпись: борт, номер вылета, фазу, высоту,
время. Переключатели слоёв и фильтр по борту масштаб не сбрасывают. В углу —
высота обзора и линейка масштаба.

### 3.4 Расписание

Вкладка «Расписание»: полоса — вылет, штриховка — ожидание на земле ради
разведения бортов; у борта — число вылетов; время — UTC, если задано начало
работ, иначе от начала работ. Таблица бортов ведёт к борту на карте и к его
заданию KML; ниже — все вылеты подробно.

### 3.5 Подсказка по флоту

Панель «Подсказка по флоту» под формой расчёта отвечает на вопросы о пуле:

- **«Срок при N бортах»** — сколько займёт работа, если взять N бортов;
- **«Сколько бортов к сроку»** — наименьшее N, при котором успеваем;
- **«Срок при каждом N»** — от одного борта до всего пула.

Для каждого N считается полный план с проверкой безопасности; до нажатия панель
говорит, сколько будет расчётов и сколько примерно ждать. Ответ — фразой и
таблицей расчётов (срок, ресурс, вылеты, состав). «Показать план ответа на карте» делает
план подсказки текущим расчётом со всеми выгрузками. Больше бортов — не всегда
быстрее: подсказка об этом предупреждает и называет наименьшее N с почти лучшим
сроком.

### 3.6 Срок или ресурс

Панель «Срок или ресурс» отвечает, сколько ресурса техники стоит закончить работы
раньше. «Построить фронт» считает шесть планов: края — «минимум срока» и
«минимум ресурса», между ними — самый экономный план к четырём промежуточным
срокам. Итог — фразой («быстрее всего — 2 ч 50 мин за 20 ч 45 мин ресурса;
экономнее всего — …»), графиком «срок — ресурс» и таблицей. Точки, соединённые
линией, — выбор «быстрее или дешевле»; пустой кружок — план, который соседний
не хуже ни по сроку, ни по ресурсу. Одинаковые планы в таблице склеены. Щелчок
по точке или строке выбирает план, «Показать план … на карте» делает его
текущим расчётом со всеми выгрузками. Срок задания здесь не учитывается.

### 3.7 Где поставить ещё площадку

Панель «Где поставить ещё площадку» предлагает место дополнительной площадки и
проверяет его расчётом. Кандидаты — у компактных скоплений самой дальней от
площадок работы (10, 20 и 30% площади); место — центр наименьшего круга вокруг
скопления, вне запретных зон. Каждый кандидат и расчёт «как есть» — полные
планы; в обоих площадки бортам выбирает расчёт. Итог — фразой («Лучшее место —
площадка для дальних 20% площади: срок 56 мин вместо 58 мин (−4%)») и таблицей;
у выбранного кандидата — координаты. «Показать план с этой площадкой на карте»
открывает пробный план: новая площадка на карте выделена и подписана
«Предложенная площадка».

### 3.8 История расчётов

Готовые планы хранятся на сервере (последние 30) и переживают его перезапуск.
Панель «История расчётов» под подсказкой перечисляет их — сценарий, время,
итог; «открыть» показывает план со всеми выгрузками без пересчёта. Над
результатом тогда стоит пометка: параметры сценария могли с тех пор
измениться.

### 3.9 Техника

- **Парк** — борта с моделью, нагрузкой, отметкой «в строю», комплектами АКБ и
  заметкой. Хранится на сервере. «Взять борта в строю из парка» в редакторе
  флота делает пул расчёта из парка.
- **Модели** — характеристики каждой модели каталога; у каждого числа — откуда
  оно: «документ» (документация производителя), «расчётное» (производитель не
  публикует — выведено из других характеристик, с объяснением), «нет в
  документах». Любое число можно поправить (пометка «изменено», возврат к
  каталогу — по полю, по модели или целиком), модель — скрыть из работы, можно
  завести свою. Изменённые и свои модели уходят в расчёт вместе со сценарием,
  план об этом предупреждает.
- **Полезная нагрузка** — камеры по классам, с источником чисел и тем, чего нет в
  документах.

## 4. Как читать план

- **Высоты** — над поверхностью (AGL), рельеф плоский.
- **Высота съёмки** одна на вылет и следует из GSD и камеры; перелёты идут на
  эшелоне борта выше его съёмки.
- **Ветер** задаётся «откуда дует». Он решает, удержит ли борт путевую скорость
  на галсе, и выбирает направление галсов; во время и расход не входит.
- **Запас заряда** — 20%: вылет планируется так, чтобы сесть с ним.
- **Самолёт** разворачивается в защитной зоне манёвра на концах галсов; зона
  показана на карте, и её тоже проверяет краш-тест.

## 5. Выгрузка

| Файл | Что внутри |
|---|---|
| `<сценарий>.kml` | Обзор: расписание, задания всех бортов, слои сценария — для Google Earth и QGIS |
| `<сценарий>.<борт>.kml` | Индивидуальное полётное задание борта: вылеты, ключевые точки с временем, трек для шкалы времени Google Earth, расписание борта |
| `<сценарий>.geojson` | Весь план для программ: маршруты, ключевые точки, подобласти, метрики, расписание |
| `<сценарий>.schedule.csv` | Расписание всех вылетов таблицей |

Архив ZIP — все файлы разом. Полное описание — [`export_format.md`](export_format.md).

## 6. Частые вопросы

**Почему задание невыполнимо, хотя бортов много?** Смотрите причину: чаще всего
подобласть недосягаема — самолёту негде развернуться у зоны, а коптеру не
долететь с площадки. Совет «добавить площадку» показывает место на карте.

**Почему срок не сокращается с числом бортов?** Борта на одной площадке и
высоте съёмки ждут друг друга ради разведения, лишний борт добавляет подлёты.
Спросите подсказку «срок при каждом N».

**Почему план обходит препятствие, которое ниже высоты полёта?** Препятствие
обходится, если высота полёта ниже его вершины плюс запас по высоте. Рельеф не
учитывается: препятствие, записанное отметкой над уровнем моря, считается
высотой над землёй.

**Можно ли не учитывать запретную зону?** Нет: залёт в зону — нарушение, план с
ним не выдаётся никогда.

## 7. Командная строка

Ядро считает и выгружает планы без интерфейса. Команда `pareto` строит фронт
«срок — ресурс»: план «минимум срока», план «минимум ресурса» и между ними —
«минимум ресурса» к нескольким срокам; видно, сколько ресурса стоит закончить
раньше. Команда `sites` подбирает место ещё одной площадки: кандидаты — у
скоплений самой дальней от площадок работы, каждый проверен полным расчётом;
ответ — срок с каждым кандидатом против нынешнего.

```bash
python -m core.cli scenarios/demo_100km2.json -o out/                     # комплект файлов
python -m core.cli scenarios/simple.json -o out/b1.kml --board geoscan-gemini_1  # задание борта
python -m core.cli scenarios/demo_100km2.json -o out/ --mode min_resource  # режим
python -m core.cli --batch scenarios/ -o out/                              # все сценарии каталога
python -m core.cli hints scenarios/demo_100km2.json --deadline-h 6         # сколько бортов к сроку
python -m core.cli import-layers --area area.kml --zones zones.kml \
    --obstacles obstacles.kml --params params.json -o scenario.json        # сценарий из слоёв
python -m core.cli compare scenarios/ -o out/compare.md                    # оптимизатор против равного деления
python -m core.cli pareto scenarios/demo_100km2.json -o out/pareto.md      # что стоит каждый срок
python -m core.cli sites scenarios/demo_100km2.json -o out/sites.md        # где поставить ещё площадку
python -m core.cli assumptions                                             # реестр допущений
```

## 8. API

Основные маршруты (полное описание — <http://localhost:8000/docs>):

| Маршрут | Что делает |
|---|---|
| `GET /scenarios`, `POST /scenarios` | Список сценариев; сохранить сценарий JSON (с проверкой) |
| `POST /scenarios/import` | Собрать сценарий из слоёв KML и параметров; ответ — с отчётом импорта |
| `GET /scenarios/{id}/layers` | Слои сценария GeoJSON — до расчёта |
| `POST /scenarios/{id}/plan` | Запустить расчёт; ответ — задача |
| `GET /jobs/{id}` | Состояние задачи (поллинг) |
| `GET /jobs` | Все задачи, новые первыми, — вместе с сохранёнными до перезапуска |
| `GET /jobs/{id}/result`, `/schedule` | План или отчёт; расписание |
| `GET /jobs/{id}/export?format=kml\|geojson\|schedule&board=…` | Выгрузка; с `board` — задание одного борта |
| `GET /jobs/{id}/package` | Весь комплект архивом ZIP |
| `POST /scenarios/{id}/hints`, `GET /hints/{id}` | Подсказка по пулу и её состояние |
| `POST /scenarios/{id}/pareto`, `GET /pareto/{id}` | Фронт «срок — ресурс»: точки по мере расчёта, план каждой — `plan_job_id` |
| `POST /scenarios/{id}/sites`, `GET /sites/{id}` | Подбор места ещё одной площадки: расчёт «как есть» и кандидаты, план каждого — `plan_job_id` |
| `GET /vehicles`, `GET /park`, `PUT /park` | Каталог моделей; парк техники |

# Текущее состояние проекта

**Обновлено:** 2026-09-20
**Состояние одной строкой:** каркас приведён к ответам заказчика (контракт v2): конвейер «подобласти → распределение → покрытие → вылеты → расписание → краш-тест» проходит на всех сценариях, включая демо ~95 км² с 10 бортами; итог — полный план или отчёт о невыполнимости. Разведение по высоте считается от собственной высоты съёмки каждого борта, зоны манёвра самолётов разводятся друг с другом. Выгрузка — обзор плана и индивидуальное задание каждого борта: KML с ключевыми точками, треком `gx:Track` и расписанием, GeoJSON, CSV. Распределение — baseline, декомпозиция, расписание и рекомендации — простые заглушки.

Живой документ. Читается в начале каждой сессии, обновляется в конце. Формат отчёта сессии — [`AGENT.md`](../AGENT.md) §10. Требования заказчика — [`customer_qa.md`](customer_qa.md), ссылки «№N».

## 2. Что работает end-to-end прямо сейчас

**Сквозной путь ядра:** сценарий (WGS84) → проверка входа → метры → параметры съёмки по бортам → маска съёмки → подобласти → эшелоны → распределение → галсы по бортам → вылеты с обходом зон → расписание с разведением → краш-тест → план или отчёт → GeoJSON, KML, CSV на весь план и KML-задание на каждый борт.

```
python -m core.cli --batch scenarios/ -o out/
```

| Сценарий | Итог | Подобластей | Вылетов / бортов | Срок | Ресурс |
|---|---|---|---|---|---|
| `simple` | выполним | 6 из 6 | 4 / 2 | 61,3 мин | 123,7 мин |
| `medium` | выполним | 29 из 29 | 16 / 4 (с Геоскан 201) | 195,1 мин | 592,8 мин |
| `demo_100km2` | выполним | 237 из 237 | 98 / 9 (801 исключён) | 16 ч 25 мин | 66 ч 7 мин |
| `nasty` | **невыполним** | 8 из 38 не сняты | — | — | — |

`nasty` невыполним по замыслу: предел числа вылетов не даёт снять область; причина названа, рекомендация — снять предел или добавить борт. Весь прогон — около 5 секунд.

**Почему цифры изменились 2026-09-20** (было: `medium` 283,8 мин и 23 вылета, демо 14 ч 24 мин и 96 вылетов). Закрыт долг №34: эшелон перелёта отсчитывается от собственной высоты съёмки борта, а не от самой высокой во флоте.

- `medium` — **срок −31%** (283,8 → 195,1 мин), вылетов 23 → 16. Коптеры больше не поднимаются с 204 м до 486 м ради перелёта; набор и снижение перестали съедать треть вылета.
- Демо — **налёт −29 мин** (3016 → 2987), ресурс −9 мин, а **срок вырос на 2 ч** (863,6 → 984,8 мин). Две причины, обе не в физике полёта. Первая: коптеры летят на 285–405 м и обходят мачту 250 м и трубу 180 м, вместо того чтобы перелетать их на 486 м — дистанция +96 км, то есть +1 км на вылет (долг №39). Вторая, главная: baseline перекроил куски под новую ёмкость вылета, и разброс между коптерами вырос — самый загруженный получил 21 вылет, самый свободный 7. Потенциал плана при этом не изменился: налёт, делённый на 9 бортов, — 332 мин против 335 до правки. Это долг №25, задача E6 шаг 2.

**Сквозной путь API** — сохранение с проверкой → фоновая задача → поллинг → результат со статусом → расписание → выгрузка. Покрыто тестами через `TestClient`.

**Сквозной путь через браузер** — проверено 2026-09-18 после `docker compose up --build`: демо-сценарий — «План выполним», метрики и расписание совпадают с CLI (102 вылета, 16 ч 24 мин); `nasty` — «Задание невыполнимо», причины и рекомендация, выгрузка отчёта. Ошибок в консоли нет. 2026-09-19 (API через uvicorn, веб через Vite, без Docker): `medium` — метрики как в CLI, ключевые точки на карте с подписью, все восемь ссылок выгрузки (обзор в трёх форматах, архив, четыре задания бортов) отдают файлы с верными именами.

**Выгрузка сторонними разборщиками** — 2026-09-19: KML всех видов (обзор, задание борта, отчёт, файл без начала работ) разобран `@tmcw/togeojson` и форматом KML OpenLayers без ошибок; число объектов у обоих совпадает, стили разрешаются в цвета веба, треки читаются со временем.

**Не проверено:** запуск на другой машине, открытие KML в Google Earth и QGIS (их нет на машине разработки). `docker compose up --build` после слияния e8-export — проверен 2026-09-19: оба контейнера, API healthy, через прокси веба расчёт `simple`, задание борта и архив ZIP отдаются.

**Ближайшая цель:** E3 — декомпозиция по форме и направление галсов с ветром. Затем E6 шаг 2: долги №34 и №27 закрыты, ёмкость вылета считается по честным эшелонам, и разброс нагрузки между бортами стал главным, что портит срок демо (долг №25). Параллельно — E10 и E9: загрузка файлов в вебе и приём геослоёв в API.

## 3. Заглушки и временные решения

Все заглушки объявляют себя в результате: стадия попадает в `Mission.stub_stages`, в план добавляется предупреждение `stub.*`.

| Заглушка | Где | Что делает вместо реальной логики | Закроет эпик |
|---|---|---|---|
| Направление галсов | `core/coverage/strips.py` → `dominant_azimuth_deg` | Длинная сторона описанного прямоугольника маски, одно направление на всю область, без ветра | E3 |
| Декомпозиция | `core/coverage/decompose.py` | Сетка квадратов одного размера; обрезки по краям — отдельные подобласти | E3 |
| Расписание | `core/deconflict/schedule.py` | Жадно ставит вылеты по очереди и сдвигает старт на минуту, пока есть сближения, схождение зон манёвра или временная зона в окне; ожидание только на земле | E14 |
| Рекомендации | `core/advise/diagnose.py` | Правила по кодам причин; место площадки — внутренняя точка недоступных подобластей | E15 |
| Распределение | `core/allocate/baseline.py` | Не заглушка, а baseline — точка сравнения (инвариант 8). Оптимизатора ещё нет | E6 |
| Временные зоны в маршрутизаторе | `core/transit/routing.py` | Обходятся всегда, как постоянные | E5 |
| Досягаемость резервной площадки | `core/validate/checks.py` | Не проверяется — объявлено предупреждением `validate.not_checked` | E7 |

**Упрощения по решению заказчика — не заглушки:** петля разворота самолёта не строится, вместо неё — зона манёвра (№38); расход линеен по времени (№35); ветер не входит во время и расход (№36, №45); катапульта и парашют не моделируются (№39).

## 4. Принятые допущения

### 4.1 В `core/assumptions.py`

```bash
python -m core.cli assumptions
```

Происхождение числа: `measured` — из документа, `customer` — **значение заказчика** («*» в выводе), `team_assumption` — **решение команды** («!»), `derived` — по формуле. Перекрытия по типам съёмки — отдельный конфиг `data/survey_presets.yaml` с источником у каждого числа (№25).

**Значения заказчика:** отсечка заряда 20% (№34), линейная модель расхода (№35), роль ветра (№45), минимумы разделения 300 м для самолёта и 50 м для мультиротора (№37), предел флота 15 бортов (№2, №43), минимум поперечного перекрытия 50% для фото-, ИК- и мультиспектральной съёмки (№25).

### 2026-09-20 — E14: эшелоны и зоны манёвра, ветка `e14-levels`

Закрыты долги №34 и №27 — оба про разведение бортов, оба не ждали ответа заказчика. Взяты вместе: эшелон и зона манёвра проверяются одним краш-тестом.

- **№34, `core/deconflict/levels.py` — переписано назначение эшелонов.** Было: общая сетка от самой высокой съёмки флота, поэтому коптер, снимающий на 255 м, перелетал на 486 м. Стало: сетка у каждого борта своя, от его собственной высоты съёмки, а разведение держится двумя условиями — эшелон отстоит на `VERTICAL_SEPARATION_M` от высоты съёмки **любого** борта флота и от эшелонов уже назначенных бортов. Борта разбираются в порядке тесноты (запас «предел минус своя съёмка»), поэтому борт с широким запасом не занимает чужое место.
- **Найдено и исправлено по ходу:** первая редакция ставила борт на 495 м при чужом эшелоне 486 м — в 9 м вместо интервала 30 м, и это не было ни делёжем, ни нарушением, которое кто-то развёл бы. Теперь в кандидаты добавляются уже занятые эшелоны: если своего места нет, борт встаёт **вторым на чужой эшелон** (объявленный делёж, который разводит расписание), а не рядом с ним.
- Предупреждение `deconflict.levels_shared` — та же механика (долг №35), новая причина: «из N эшелонов между съёмкой X и пределом Y свободных не осталось». Прежний текст считал эшелоны коридора и после правки стал бы неверным. В `context` добавлено `room`.
- **№27, новый модуль `core/flight/maneuver.py`** — `ManeuverWindow` (зона, высота съёмки, окно времени, минимум разделения) и `maneuver_overlap`. Зона манёвра занята **всё время съёмки своей подобласти**, а не только когда через неё идёт линия маршрута: в траектории разворот — отрезок между концами галсов, а самолёт вправе крутить петлю где угодно внутри зоны (№38). Модуль общий для E7 и E14, как `core/flight/track.py`.
- **`core/validate/checks.py`:** новая проверка `_check_maneuver_separation` — пары зон разных вылетов по времени, высоте и расстоянию; нарушение `validate.maneuver_separation` с местом на карте. Сбор зон в трёх прежних проверках переведён на общий модуль — три копии одного кода убраны.
- **`core/deconflict/schedule.py`:** старт сдвигается не только при сближении траекторий, но и при схождении зон манёвра — иначе краш-тест объявлял бы невыполнимым то, что расписание умеет развести. На демо ветка вызывается 4116 раз и ни разу не срабатывает: зоны самолётов там не сходятся.
- `core/schemas.py`: **не изменён.** TS-типы не перегенерировались — нечего.
- Заведён долг №39 (эшелон не учитывает препятствия), долг №25 переписан по новым цифрам.

**Проверки:** `pytest` — 214 пройдено (4 новых: эшелон следует за своей высотой съёмки; интервал до чужой съёмки и чужих эшелонов на всех сценариях; геометрия `maneuver_overlap` по времени, высоте и расстоянию; испорченный план, где траектории разведены, а зоны манёвра сходятся, — проверка траекторий молчит, новая ловит); `ruff check` и `ruff format --check` — чисто; CLI на всех четырёх сценариях — цифры в §2, разбор роста срока демо там же. **Не проверено:** веб и Docker — код веба и API не менялся.

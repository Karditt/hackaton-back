## 2. Что работает end-to-end прямо сейчас

**Работает сквозной путь ядра:** JSON-сценарий → рабочая маска в метрах → параметры съёмки → галсы → распределение по бортам и вылетам → вылеты по фазам с ветром и энергией → валидация → KML и GeoJSON.

Проверено запуском на всех трёх сценариях:

```
python -m core.cli --batch scenarios/ -o out/
```

| Сценарий | Галсов покрыто | Вылетов / бортов | Makespan | Ошибок |
|---|---|---|---|---|
| `simple` | 13 из 13 | 4 / 2 | 60,3 мин | 0 |
| `medium` | 46 из 46 | 19 / 3 | 241,0 мин | 25 (отсев Геоскан 201 + 24 транзита сквозь зоны) |
| `nasty` | 32 из 42 | 13 / 3 | 231,3 мин | 6 (не хватило вылетов, транзиты сквозь зону) |

Ошибки в `medium` и `nasty` — ожидаемые и осмысленные, а не сбои: они показывают ровно те места, которые закрывают E5 и E6.

**После ответов заказчика оба результата недопустимы как выход сервиса.** `medium` выдаёт план, в котором 24 транзита проходят сквозь запретные зоны, — это нарушение жёсткого правила (инвариант 9). `nasty` выдаёт частичный план: 32 галса из 42 (инвариант 10). По новым правилам первый должен либо обойти зоны, либо объявить невыполнимость, второй — объявить невыполнимость с причиной «не хватает вылетов» и рекомендацией. Все три сценария — ~5 км², в 20 раз меньше масштаба заказчика.

**Работает сквозной путь API:** сохранение сценария → запуск фоновой задачи → поллинг статуса → результат со всеми стадиями → отдача файла. Покрыто тестами через `TestClient`.

**Работает сквозной путь через браузер** — проверено 2026-09-16 после `docker compose up`: интерфейс на http://localhost:5173 подтягивает сценарии из API, запускает расчёт, опрашивает статус, рисует маршруты по фазам, показывает метрики, предупреждения и признак заглушек. Цифры совпадают с CLI (`simple`: 60,3 мин, 4 вылета, 13 из 13 галсов; `medium`: 241 мин, 19 вылетов, 46 из 46). Карта сама переходит к области результата.

**Не проверено:** запуск на другой машине, открытие выгруженного KML в стороннем ПО. Работа без интернета больше не требуется (№16).

**Ближайшая цель** — фаза 1b из [`architecture.md`](architecture.md) §5: принять контракт v2 одним изменением, завести демо-сценарий ~100 км² и невыполнимый сценарий, снять с конвейера опровергнутые допущения (§6), разблокировать RGB для Геоскан 201. Только после этого — E3 (декомпозиция), E6 шаг 2 и E14.

Каждая запись имеет вид «имя = значение [единица] + источник + обоснование» и помечена одним из трёх происхождений: `measured` (физическая константа или ТТХ из документа), `team_assumption` (**решение команды, источника не существует**), `derived` (выведено по явной формуле).

Ключевые допущения, влияющие на результат сильнее всего. Колонка «После ответов заказчика» — что с допущением делать; в код ещё не перенесено (§6).

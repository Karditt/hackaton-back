## 2. Что работает end-to-end прямо сейчас

**Работает сквозной путь ядра:** JSON-сценарий → рабочая маска в метрах → параметры съёмки → галсы → распределение по бортам и вылетам → вылеты по фазам с ветром и энергией → валидация → KML и GeoJSON.

Проверено запуском на всех трёх сценариях:

```
python -m core.cli --batch scenarios/ -o out/
```

| Сценарий | Галсов покрыто | Вылетов / бортов | Makespan | Ошибок |
|---|---|---|---|---|
| `simple` | 13 из 13 | 4 / 2 | 60,3 мин | 0 |
| `medium` | 46 из 46 | 19 / 3 | 241,0 мин | 25 (отсев Геоскан 201 + 24 транзита сквозь зоны) |
| `nasty` | 32 из 42 | 13 / 3 | 231,3 мин | 6 (не хватило вылетов, транзиты сквозь зону) |

Ошибки в `medium` и `nasty` — ожидаемые и осмысленные, а не сбои: они показывают ровно те места, которые закрывают E5 и E6.

**Работает сквозной путь API:** сохранение сценария → запуск фоновой задачи → поллинг статуса → результат со всеми стадиями → отдача файла. Покрыто тестами через `TestClient`.

**Работает сквозной путь через браузер** — проверено 2026-09-16 после `docker compose up`: интерфейс на http://localhost:5173 подтягивает сценарии из API, запускает расчёт, опрашивает статус, рисует маршруты по фазам, показывает метрики, предупреждения и признак заглушек. Цифры совпадают с CLI (`simple`: 60,3 мин, 4 вылета, 13 из 13 галсов; `medium`: 241 мин, 19 вылетов, 46 из 46). Карта сама переходит к области результата.

**Не проверено:** запуск на другой машине, открытие выгруженного KML в стороннем ПО, работа карты без интернета (долг №3).

Ближайшая цель: закрыть №13 (собрать образы, увидеть карту в браузере), затем E3 — выбор направления галсов расчётом, и E6 шаг 2 — конструктивная эвристика.

## 4. Принятые допущения

### 4.1 Перенесены в `core/assumptions.py`

Файл создан. Реестр машиночитаемый, печатается командой:

```bash
python -m core.cli assumptions --team-only
```

Каждая запись имеет вид «имя = значение [единица] + источник + обоснование» и помечена одним из трёх происхождений: `measured` (физическая константа или ТТХ из документа), `team_assumption` (**решение команды, источника не существует**), `derived` (выведено по явной формуле).

Ключевые допущения команды, влияющие на результат сильнее всего:

| Допущение | Значение | Чем обосновано |
|---|---|---|
| `FIXED_WING_BANK_ANGLE_DEG` | 30° | **Закрывает пробел, блокировавший E4.** Радиуса разворота Геоскан 201 нет в источнике; он выводится как `r = V²/(g·tan φ)`. При выведенной крейсерской скорости даёт ≈128 м |
| `FIXED_WING_CRUISE_FRACTION_OF_RANGE` | 0,5 | Крейсерская скорость 201 не выделена в документе, дан диапазон 64–130 км/ч. Берётся середина |
| `MULTIROTOR_CRUISE_FRACTION_OF_MAX` | 0,7 | У 801 и Gemini в буклетах только максимальная скорость. Полёт на максимуме съедает запас на ветер |
| `BATTERY_RESERVE_FRACTION` | 0,20 | Неснижаемый резерв заряда нигде не публикуется. Прямо влияет на число вылетов и makespan |
| `BATTERY_SWAP_TIME_S` | 600 с | Замена, а не зарядка: заряд АКБ Gemini — около 105 мин, повторный вылет на том же комплекте бессмыслен |
| `VEHICLE_PREP_TIME_S` | 300 с | Подготовка борта к первому вылету. Входит в makespan |
| `POWER_FRACTION_BY_PHASE` | 0,6–1,6 | Разбивки расхода по фазам нет ни в одном источнике |
| `NFZ_BUFFER_M` | 50 м | Нормативного буфера вокруг запретной зоны в ТЗ нет |
| `WIND_SAFETY_FRACTION` | 0,8 | Запас до паспортного предельного ветра |
| `WIND_MODEL` | `uniform_constant` | Ветер постоянен по области и по высоте, профиля и порывов нет |
| `TERRAIN_MODEL` | `none` | ЦМР в объём не входит; высоты относительно точки старта, KML — `relativeToGround` |
| `DEFAULT_FORWARD_OVERLAP` / `DEFAULT_SIDE_OVERLAP` | 0,80 / 0,60 | Типовые значения для фотограмметрии, если сценарий не задал свои |

Этот список — готовая заготовка раздела «известные ограничения», который требует ТЗ (E13).

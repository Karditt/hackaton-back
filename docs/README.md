# Документация

Сервис планирования и распределения беспилотных авиационных работ: делит
съёмку большой области между разнотипными БВС, строит полётное задание каждого
борта и общее расписание, проверяет план краш-тестом и выгружает KML, GeoJSON,
CSV — или объясняет, почему задание невыполнимо и что добавить.

## С чего начать

| Кому | Что читать |
|---|---|
| Всем, 10 минут | [Пояснительная записка](explanatory_note.md) — задача, решение, алгоритм, результаты против равномерного деления |
| Пользователю | [Руководство пользователя](user_guide.md) — запуск, вход, интерфейс, итог, выгрузка, командная строка |
| Разработчику, интегратору | [Описание API](api.md) и [архитектура](architecture.md) |
| Специалисту по БАС | [Известные ограничения](known_limitations.md) — упрощения модели и реестр чисел с источниками; [источники данных](external_sources.md) — ТТХ бортов, подложка, рельеф |

## Все документы

| Документ | Что внутри |
|---|---|
| [`explanatory_note.md`](explanatory_note.md) | Пояснительная записка: задача, решение, модель предметной области, алгоритм, режимы, результаты, как проверить |
| [`user_guide.md`](user_guide.md) | Руководство пользователя: запуск, входные данные, работа в интерфейсе, как читать план, выгрузка, частые вопросы, CLI, API |
| [`api.md`](api.md) | Описание API: модель работы, пример от файлов до заданий бортов, все маршруты, ошибки. Интерактивно — <http://localhost:8000/docs> |
| [`architecture.md`](architecture.md) | Архитектура: слои, конвейер расчёта, модули ядра, производительность, хранение, запуск, ключевые решения |
| [`input_formats.md`](input_formats.md) | Входные данные: слои KML области, зон, препятствий и площадок; предложенный формат высот и времени действия зон |
| [`export_format.md`](export_format.md) | Выходные данные: GeoJSON, KML, расписание CSV, задание каждого борта |
| [`known_limitations.md`](known_limitations.md) | Известные ограничения и реестр допущений с источниками |
| [`external_sources.md`](external_sources.md) | Источники: ТТХ БВС, подложка, рельеф, препятствия, спецификации форматов |
| [`sources/`](sources/) | Документы производителя, по которым заполнен каталог техники, и ТЗ кейса |

Рабочие документы команды (статус, план работ, ответы заказчика на вопросы,
правила разработки) — в [`dev/`](dev/); для проверки решения они не нужны.

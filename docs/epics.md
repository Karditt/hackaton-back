# GEOSCAN — эпики

Сервис планирования и распределения беспилотных авиационных работ.
Без распределения по исполнителям и без оценок. Только состав работ.

Приоритеты: **P0** — без этого решения нет · **P1** — за это ставят баллы по критериям оценки · **P2** — если останется время.

## E0 — Каркас, контракт данных, среда запуска
**P0 · зависит от: —**

Скелет репозитория, доменные схемы (Scenario, Vehicle, Strip, Leg, Sortie, Mission), заглушки для стадий конвейера, реестр физических допущений, набор тестовых сценариев (простой / средний / «злой» — с дырками и запретными зонами впритык к границе), запуск одной командой.

**Не входит:** авторизация, миграции, CI/CD, очередь задач.

**Готово, когда:** проект поднимается на чистой машине одной командой, и любая стадия конвейера может работать на заглушках соседних.

---

## E1 — Геопространственное ядро
**P0 · зависит от: E0**

Выбор метрической проекции и конвертеры координат. Вся геометрия считается в метрах, географические координаты живут только на границах системы. Подготовка рабочей маски области: буфер вокруг запретных зон, вычитание из полигона съёмки, обрезка по границам разрешённого воздушного пространства, валидация геометрии.

**Готово, когда:** полигон с несколькими отверстиями корректно превращается в рабочую маску, а расстояния сходятся с эталонными.

---

## E2 — Модель съёмки
**P0 · зависит от: E1**

Из типа съёмки и требований к качеству получить параметры полёта: высоту, ширину полосы захвата, шаг между галсами из перекрытий, предельную скорость по интервалу срабатывания сенсора. Пресеты для RGB, мультиспектральной, ИК, LiDAR и геофизической съёмки со своей физикой у каждого. Матрица совместимости «борт × полезная нагрузка».

**Готово, когда:** по сценарию возвращается обоснованный набор параметров съёмки, а несовместимые пары «борт-нагрузка» отсекаются.

---

## E3 — Покрытие области галсами
**P0 · зависит от: E2**

Декомпозиция области, генерация галсов с параметризуемым направлением, обрезка по рабочей маске. Выбор оптимального направления перебором по углу с целевой функцией, учитывающей ветер и число разворотов. Перекрытие на стыках подобластей, чтобы в итоговом ортофотоплане не было дыр.

**Готово, когда:** галсы покрывают всю область, а направление выбирается расчётом, а не задаётся константой.

---

## E4 — Модель полёта: ветер, время, энергия
**P0 · зависит от: E1**

Кинематика с ветром: путевая скорость, угол упреждения, проверки допустимого бокового и встречного ветра. Модель времени и расхода энергии по фазам полёта (взлёт, набор, транзит, галс, разворот, снижение, посадка) с неснижаемым резервом заряда. Развороты с минимальным радиусом для бортов самолётного типа, удлинение галсов за границу полигона, схема разворота «через галс», когда шаг меньше диаметра разворота.

**Готово, когда:** стоимость любого участка и выполнимость любого вылета считаются честно, а не как «длина делить на скорость».

---

## E5 — Транзит с обходом запретных зон
**P1 · зависит от: E1**

Граф видимости по границам запретных зон, кратчайшие перелёты между галсами и до площадок с огибанием препятствий. Промежуточное состояние — прямая линия с предупреждением при пересечении запретной зоны.

**Готово, когда:** ни один транзитный участок не проходит сквозь запретную зону.

---

## E6 — Распределение по флоту и оптимизация
**P0 · зависит от: E3, E4**

Ядро задачи, разворачивается в три шага, каждый из которых оставляет систему работоспособной:

1. **Baseline** — деление на равные полосы по числу бортов. Всегда даёт результат, позже служит точкой сравнения.
2. **Конструктивная эвристика** — сборка вылетов с учётом остатка заряда, несколько вылетов на борт со сменой батареи, несколько площадок взлёта, разнотипный флот.
3. **Локальный поиск** — перенос галсов между бортами, улучшение порядка внутри вылета, целевая функция вида `α·makespan + (1−α)·суммарный налёт`.

**Готово, когда:** при крайних значениях α получаются визуально разные планы.

---

## E7 — Валидация выполнимости и безопасности
**P1 · зависит от: E4, E6**

Проверка готового плана: траектория целиком (включая петли разворотов) не выходит за разрешённое воздушное пространство и не задевает запретные зоны; энергетический баланс сходится с резервом; ветер в допуске; резервная площадка достижима из любой точки маршрута. Разведение бортов в воздухе — эшелонированием по высоте либо проверкой непересечения по времени.

**Готово, когда:** план несёт список предупреждений, а проблемные участки можно подсветить.

---

## E8 — Экспорт полётных заданий
**P0 · зависит от: E6**

KML и GeoJSON с явным режимом высоты, разбиением по фазам полёта, ключевыми точками, высотой, скоростью, площадками старта и посадки. Опционально — формат наземной станции (QGroundControl / Mission Planner).

**Готово, когда:** выгруженный файл открывается в стороннем ПО и выглядит корректно.

---

## E9 — API и сервисный слой
**P0 · зависит от: E0**

Приём и хранение сценариев, запуск конвейера фоновой задачей, опрос статуса, выдача результата, доступ к промежуточным стадиям конвейера, отдача файлов экспорта.

**Не входит:** многопользовательский режим, права доступа.

---

## E10 — Редактор сценария
**P0 · зависит от: E9**

Карта с офлайн-фолбэком тайлов. Рисование области съёмки, запретных зон, границ воздушного пространства. Расстановка площадок взлёта-посадки и резервных. Панель параметров: тип съёмки, требования к качеству, состав флота, ветер. Сохранение и загрузка сценария файлом.

**Готово, когда:** сложный сценарий задаётся мышью за пару минут и переиспользуется без перерисовки.

---

## E11 — Визуализация и анализ результата
**P0 базовая отрисовка / P1 остальное · зависит от: E8, E10**

Маршруты по бортам на карте с ключевыми точками и параметрами участков. Инспектор промежуточных стадий конвейера. Анимация полёта всех бортов по общему таймлайну. Диаграмма загрузки бортов по вылетам. Панель метрик. Подсветка предупреждений валидатора. Переключатель критерия оптимальности.

**Готово, когда:** происходящее понятно без словесных пояснений.

---

## E12 — Доказательство эффективности
**P1 · зависит от: E6**

Прогон на наборе сценариев разного масштаба. Таблица сравнения с baseline в процентах. График масштабируемости: время расчёта и качество решения при росте площади и числа бортов. Фронт Парето по сетке α с возможностью выбрать точку и увидеть соответствующий план.

В критериях оценки прямым текстом стоят «эффективность построенных маршрутов» и «масштабируемость». Без сравнения с baseline эффективность нечем измерить.

**Готово, когда:** есть конкретная цифра выигрыша относительно наивного распределения.

---

## E13 — Документация, демо, защита
**P0 · ведётся сквозь весь проект**

Разделы по пунктам ТЗ: архитектура, алгоритм оптимизации, инструкция запуска, описание API, руководство пользователя, известные ограничения (вырастают из реестра допущений в E0). Сценарий демонстрации, прогоны целиком, видеозапись как бэкап. Презентация.

**Готово, когда:** посторонний человек запускает решение по инструкции без вопросов.

---

## Что не режется при урезании объёма

Переключение критерия оптимальности (E6) и сравнение с baseline (E12). Без этих двух вещей решение выглядит как рисовалка галсов, а не как сервис оптимизации.
